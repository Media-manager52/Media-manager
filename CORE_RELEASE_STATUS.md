## Complete-season acceptance stop

- Selected identity: The Nurse (2023), season 1; TMDB `221802`, TVDB `428682`, IMDb `tt24948454`; four expected episodes. Exact provider identity queries proved it absent from Plex before the run and remained zero after the safe stop.
- Release: `The.Nurse.S01.2023.Complete.1080p.Netflix.WEB-DL.AVC.DDP.5.1-DBTV`. Pre-download Danish-subtitle evidence was unknown and therefore neutral.
- Attempts: NZBFinder queue `15767`, then NZBgeek queue `15768`. Each frozen inventory contained the same four assets and 7,641,691,115 bytes. Both were retained and remain visible as `unverified`; the second is `exhausted`.
- Verification: every episode was 1920×1080 H.264 with Danish E-AC-3 audio. Embedded subtitles were Chinese and English (including explicitly tagged English forced tracks); no recognized sidecar existed and no Danish subtitle was guessed.
- Safety result: no publication records, Plex scan requests, or Plex confirmations were created. Workflow `01a05846-d3ed-7747-b022-11302659a092` stopped at `subtitle_requirements_unverified` after 22 minutes 30 seconds.

## Defects found during the season run

- **Fixed — Seerr query compatibility:** Seerr rejected form-style `+` space encoding. Search now emits `%20`, with a regression test (`a2dd00a`).
- **Fixed — Newznab season normalization:** reliable provider season metadata such as `S01` conflicted with title-inferred `1`, incorrectly holding valid packs. Both now evaluate as canonical `1` while the raw field remains evidence (`98c8cc8`).
- **Fixed — cross-index exact package deduplication:** a bounded strict NZB segment-manifest identity is stored per job. Packages that already failed subtitle verification in the same workflow are skipped without AltMount submission or attempt consumption; exclusions remain exact and workflow-scoped (`c7782ea`).
- **Fixed — redirect source credential handling:** source API-key query components are removed before every redirected request while unrelated redirect tickets remain, with all DNS pinning/TLS/header protections intact (`3efdf71`). Live evidence shows Treasure Maps answers 403 without that key, so its grabs remain safely incompatible; the indexer was not disabled or globally blocked.
- **Fixed — historical Newznab observation credentials:** bounded direct, nested, encoded, malformed, repeated, and provider-specific query sanitization now runs before evidence persistence and at the database boundary. Migrations 27–28 retained all 10,876 observations while sanitizing 3,265 affected rows; exact configured-secret matches, unredacted credential-query patterns, and remaining sanitizer differences are all zero (`323cd9f`).
- **Fixed — timing-biased release selection:** equal-score candidates no longer favor the indexer that responded last; durable indexer/native identities provide the deterministic tiebreak (`2f18e22`).
- **Fixed — cooldown worker blocking and attempt accounting:** persisted pacing now defers the event without holding the single worker or consuming a retrieval attempt; redirected 403 responses no longer invalidate source credentials, and terminal access rejection excludes only the exact release (`4d9033a`, `d188840`).
- **Fixed — Plex series provider identity lookup:** exact series confirmation now loads the show detail when Plex section summaries contain only an internal GUID, while still requiring every expected episode path (`9e5025c`).
- **Fixed — completed retry truthfulness:** after the verified second attempt succeeded, the retained first attempt still appeared as `queued`. Schema 26 now records it as `succeeded`, backfills the live result, and renders the durable outcome accurately in the owner UI (`7229e8b`).
- **Completed credential action — Treasure Maps:** local secret-reference metadata, timestamps, and a non-reversible file-to-runtime fingerprint comparison prove the currently loaded credential is the replacement loaded after redirect-hardening commit `1253d7b`. The credential was neither displayed nor contacted during closeout. The confirmed Adolescence result used NZBFinder.
