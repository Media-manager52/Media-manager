# System invariants

These are the guarantees Media Manager gives its owner. They are not
preferences: a change that weakens one is a bug, even if every other test
passes. An agent may propose changing an invariant in a pull request that
says so in its title; it must never weaken one silently.

Each invariant names the tests that prove it. `tests/ci/test_invariants_map.py`
fails if a named test no longer exists, so renaming or deleting a test forces
this file to be updated. **Gap** marks an invariant whose proof is incomplete;
closing gaps is tracked work, not optional polish.

| ID | Invariant | Proven by |
|---|---|---|
| S01 | A working published asset is never deleted or overwritten because a search failed, a mount was unavailable, a request timed out, verification was incomplete or a media-server scan was missing. | `TestFailedUpgradePublicationPreservesCurrentPublication`, `TestFailedUpgradeVerificationPreservesCurrentPublication`, `TestMountOutageDefersInsteadOfFailing`, `TestRemoveSymlinkNeverTouchesRealMedia` |
| S02 | A new version replaces the current one only after the media server has confirmed it at the exact expected path and identity. | `TestFailedUpgradePublicationPreservesCurrentPublication`, `TestConfirmationReportsIdentityMismatchForExactPath`, `TestConfirmationByPathRequiresContainingLocation` |
| S03 | Destructive file operations touch only the exact recorded target and fingerprint, never real media behind a link. | `TestRemoveSymlinkRequiresExactRecordedTarget`, `TestMoveAndRemoveRegularFileRequireExactFingerprint`, `TestRemoveSymlinkNeverTouchesRealMedia`. **Gap:** `internal/recycle` has no tests. |
| S04 | A hard requirement (resolution, language, audio language) cannot be offset by a preference score, and `unknown` never counts as `pass` unless the policy explicitly holds or allows it. | `TestEvaluateUnknownEvidenceStaysUnknown`, `TestRequiredAudioHoldsUntaggedReleasesUnlessItIsTheOriginalLanguage`, `TestApplyPresetPreservesHardRulesAndLanguagePreferences`, `TestRequiredAudioAcceptsIndexerReportedDanishAudio` |
| S05 | Claims (a release name, an indexer attribute), measurements (ffprobe), mount state and media-server visibility are separate facts with their source; a claim is never reported as a measurement. | `TestAltMountProgressIsReportedOnlyAsObserved`, `TestParseRejectsUnknownOrMissingVideoEvidence`, `TestParseSearchReadsProviderLanguageAttributeAsAudioLanguages` |
| S06 | Evidence used to select a release is immutable and stays traceable; re-scoring adds history instead of rewriting it. | `TestPersistSearchRescoredHeldObservationPreservesHistoryAndIsIdempotent`, `TestPersistSearchConcurrentAttemptsDoNotDuplicateObservation`, `TestWorkflowCandidateObservationsLoadsStoredEvidenceReadOnly` |
| S07 | External submissions are recorded before the side effect; an ambiguous outcome is reconciled, never blindly re-sent. | `TestActiveSubmissionIsNotRetransmitted`, `TestInterruptedSubmissionRecoveryIsTruthful`, `TestTransferRegularFileVerifiesAndReconcilesUnknownOutcomes` |
| S08 | Background work is idempotent: a retried, deferred, panicking or abandoned handler cannot duplicate or overwrite newer decisions. | `TestDeferredOutboxWorkDoesNotConsumeAnAttempt`, `TestRunHandlerTurnsAPanicIntoARetry`, `TestRunHandlerAbandonsAHandlerThatNeverReturns`, `TestHeldRescoreConcurrentPersistenceDoesNotDuplicateVersion`, `TestUpdateQualityProfileRejectsStaleEditAndKeepsNewerRequiredRules` |
| S09 | Indexer budgets, pacing and cooldowns persist across restarts; retries honour `Retry-After`; one request is in flight per indexer. | `TestPersistedCooldownDefersWithoutHoldingSchedulerSlots`, `TestRateLimitHonorsRetryAfter`, `TestSchedulerAllowsOnlyOneInflightPerIndexer`, `TestRollingBudgetsReserveBeforePermitAndSeparateQueriesFromGrabs`, `TestBackgroundSearchUsesAtMostFirstSixtyPercentOfQueryBudget`, `TestFeedWaitsForPacingSlotButNotFailureCooldown`, `TestFeedIntervalFollowsUploadRateWithinBoundsAndBudget` |
| S10 | Path operations stay inside their configured root, also through symlinks and container path translation. | `TestInspectWithinRejectsPathEscapeAndSymlink`, `TestPublishSymlinkCannotEscapeThroughSymlinkedParent`, `TestValidateRelativeRejectsEscapes`, `TestMoveSymlinkRejectsEscapes`, `TestValidatePlanPinsPlexVisibleTarget` |
| S11 | A season pack satisfies only the episodes proven present in its inventory; the release name alone never proves coverage. | `TestNumberedInventoryPreservesExactCoverageAndPaths`, `TestCollectionInventoryVerifiesExactRequestedScopeAndKeepsFailures`, `TestAnnualSeasonPackLabelsKeepExactInventoryGate`, `TestRenderEpisodeSetRejectsNonContiguousCoverage` |
| S12 | An upgrade cannot silently regress a required language or other contract dimension and must be a strict improvement. | `TestUpgradeBaselineRequiresStrictImprovement`, `TestUpgradeSearchContextKeepsVerifiedNoSubtitleEvidence` |
| S13 | No probe reads or decodes a whole virtual file; every probe has a byte and time budget. | `TestBoundedBufferStopsAtLimit`, `TestInspectWithinDefersAnFFprobeTimeout`, `TestInspectWithinReportsZeroFilledFiles` |
| S14 | An unavailable mount is not a missing or corrupt file; it defers work and never erases earlier evidence. | `TestMountOutageDefersInsteadOfFailing`, `TestAltMountMountHealthReportsEachEnabledClient` |
| S15 | A media-server scan acknowledgement is not publication; confirmation needs the exact path and identity. | `TestPlexConfirmationWindowStartsAtRefresh`, `TestConfirmationReportsIdentityMismatchForExactPath`, `TestConfirmationAcceptsExactPathWhenPlexHasNoProviderIdentity` |
| S16 | Adoption of existing media is planned before it is applied and can be rolled back; original files are preserved. | `TestBuildApplyAndRollbackAdoptionOperations`, `TestCrossRootAdoptionTransfersAndRollsBackVerifiedFiles` |
| S17 | Backups are verified by an isolated restore; production deploys take a backup first. | `TestCreateAndVerifyUsesIsolatedRestoreLifecycle`, `tests/ci/test_deploy_broker.py` |
| S18 | Provider credentials and the owner token never appear in API responses, stored observations, logs or client configuration. | `TestSanitizeProviderValueRemovesCredentialQueriesAndPreservesMetadata`, `TestSanitizeObservationWithCredentialRemovesProviderSpecificAliases`, `TestStreamingChoiceSurvivesARestart`. The Nuvio addon holds only the player token (S19). |
| S19 | The player token (`PLAYER_TOKEN`) opens only the reviewed playback routes (library, title lookup and requests, streaming, stream preparation) and is refused on every other route; it is never the owner token. Stream preparation returns only a path on the read-only AltMount mount: the AltMount API key and AltMount's download key never leave Media Manager. | `TestPlayerTokenOpensOnlyThePlaybackRoutes`, `TestPlayerRoutesStillRefuseMissingOrWrongTokens`, `TestPlayerTokenIsOptionalLongAndDistinctFromOwner`, `TestStreamingPrepareSubmitsToAltMountAndReturnsOnlyTheMountPath`, `TestStreamClientPreparesWithAPIKeyAndReturnsOnlyThePath` |
| S20 | Reading an indexer's newest uploads never selects, downloads or publishes anything. A match brings the title's own search forward; that search asks the indexers itself and applies the profile's rules unchanged. The worker opens a new round, for a match or because the title's own rescan found a release, only where the owner's own start-next-round would be accepted (waiting workflow, exhausted round, a newly observed eligible untried release held by discovery, unchanged policy, retained-output limit not reached), at most once per title per 24 hours over both paths and recorded as actor `worker`; a refusal writes nothing but the refused discovery generation. `FEED_OPEN_ROUNDS=off` leaves every new round to the owner. | `TestFeedMatchBringsTheScheduledSearchForwardAndNothingElse`, `TestFeedWatcherBringsAWaitingTitlesSearchForward`, `TestFeedMatchForATitleThatIsNoLongerWaitingChangesNothing`, `TestFeedMatchAgreesWithConstrainMediaMatch`, `TestFeedMatchOpensTheNextRoundTheOwnerActionWouldOpen`, `TestFeedMatchOpensNoRoundTheOwnerActionWouldRefuse`, `TestFeedDiscoveryThatFoundAReleaseOpensTheRoundOnALaterPass`, `TestRescanFoundReleaseOpensTheNextRoundOncePerDay`, `TestRescanFoundRoundRefusalWritesNothingAndIsNotAskedAgain` |
| S21 | A shared season answer never widens what an episode workflow may download. It is used only when complete, at most 12 hours old, newer than the workflow, and older than no newest-uploads match and no owner search for that workflow; each episode keeps only the releases its own scope rules accept or hold and evaluates them under its own policy. Anything else asks the indexer. | `TestEpisodesOfOneSeasonShareOneSeasonSearch`, `TestSeasonSearchIsNotSharedWhenTooFewEpisodesAreMissing`, `TestSharedSeasonResponseServesOnlyWhatAnEpisodeSearchWouldStillFind`, `TestSearchAllPagesReportsWhetherEverythingWasRead` |
| S22 | The learned Danish record of a release group only orders releases or holds them; it never makes a release eligible and never replaces measuring the download. A release is held only when its name and facts give no Danish clue, the policy requires Danish and the title is not originally Danish, and its group has at least 20 measured downloads under the same kind of requirement with Danish in at most one in twenty. | `TestHoldUnlikelyDanishGroupsHoldsOnlyProvenBadGroups`, `TestDanishGroupRecordsLearnFromMeasuredOutputs`, `TestDanishRankingTriesGroupsThatUsuallyHaveDanishFirst` |
| S23 | The search after a failed release reuses the answers of the search that selected it only when they are complete, at most two hours old, from the same acquisition round and indexer set, and older than no newest-uploads match and no owner search of the workflow. Every reused release is evaluated again under the current rules and exclusions, so the failed release is never selected again; any mismatch asks every indexer as before. | `TestRetryAfterFailedReleaseReusesTheSearchThatFoundIt` |
