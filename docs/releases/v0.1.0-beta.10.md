## What changed since v0.1.0-beta.9

The [changelog](../../CHANGELOG.md) section `0.1.0-beta.10` lists every change
(PRs #204 to #207). The main themes:

- **The newest-uploads reader no longer loses its place** (#204). It remembers the
  last 1,000 uploads it saw across restarts, reads up to ten pages to reach its
  previous read, counts reads that did not get that far, and also brings a new
  episode's first search forward.
- **Date-named shows are searched by date** (#205). An old episode of a show
  numbered by broadcast year asks with the series ID and air date (the Newznab
  daily-episode form) and with its shortest name plus the date.
- **A search schedule instead of blind repeats** (#207). A title that found
  nothing is searched again after 30 minutes, 6 hours and a day, then monthly
  (weekly for titles from this or last year); a title whose round is used up is
  rescanned after a day, a week, then monthly. A fitting new upload still
  brings the search forward at once.
- **New README screenshots** of the current interface (#206).

The rules for checking language and quality did not change, and every file is
still measured after download. Answers to the new date requests go through the
same identity, date mapping, language and quality rules as before. Newznab
pacing, cooldowns, redirect pinning and secret sanitization are unchanged.

Use [../operations/install-release.md](../operations/install-release.md) with:

```sh
MEDIA_MANAGER_API_IMAGE=ghcr.io/media-manager52/media-manager-api@sha256:65e7baa952ceefbb9195526302cbba6e4b92aacb083e2b1fc7dc83c15f3fdeb0
MEDIA_MANAGER_UI_IMAGE=ghcr.io/media-manager52/media-manager-ui@sha256:cafe4da286a9cfa3345a55a79bacbc9cf8b9e7641c9410cfeaaaa647b1f12c2b
MEDIA_MANAGER_VERSION=0.1.0-beta.10
MEDIA_MANAGER_COMMIT=03e1c1a4cfe59937a48312354c4eb3587a094b11
```

Upgrading from `v0.1.0-beta.9` runs migration 0063, which adds four columns to
`indexer_feed_state` (the remembered upload IDs and read counters). No existing
data is rewritten. Create an encrypted backup first as usual. A rollback starts
the `v0.1.0-beta.9` image pair; the new columns are then unused. Titles already
scheduled keep their next search time; the new schedule applies from their
next search.

## Verification

- **CI:** the runs in the identity table.
- **Production:** the owner's library runs this commit (schema 63). The API
  answered ready after each deploy and the server log showed no error line.
  The newest-uploads reader made 134 reads on eight indexers in the first hours
  with no gap. In the 3.5 hours after the date search went live, 112 more
  episodes of date-named wrestling shows reached Plex and the number waiting
  fell from 278 to 147. Indexer queries were about 1,150 to 1,800 per hour in
  the afternoon before the search schedule went live, against about 3,500 to
  4,200 per hour on the morning of the same day.
- **Security:** zero open Dependabot alerts and `npm audit --omit=dev` reports
  zero vulnerabilities at tagging time.

## Known limitations

- `linux/amd64` only; ARM64 is not built.
- The search schedule went live shortly before tagging; its effect on the daily
  query count has not been measured yet. It applies to each title from its next
  search, so the effect builds up over the following days and weeks.
- A release that the newest-uploads reader cannot match to a title (for example
  under a name none of the title's saved names covers) is found only by the
  monthly safety search.
- Every indexer is still asked on every search; indexers that rarely add a
  usable release are not yet asked less often.
- **Fejllog** shows failures stored in the database, not the server's own
  process log.
- A Danish name does not count as proof of Danish audio. A DANiSH release with
  untagged audio is rejected in libraries that require Danish audio.
- **Overtag bibliotek** and resuming an interrupted **Flyt** are covered by
  automated tests but have not been used on real titles.
- No installation on a genuinely clean third-party host has been recorded.
- Off-site backup is not built in.
- Restore is documented and operator-run, not automated.
- The web UI is Danish only.
- Only the supported stack (Seerr, Media Manager, Newznab, AltMount, Plex) is
  tested.
