## What changed since v0.1.0-beta.7

The [changelog](../../CHANGELOG.md) section `0.1.0-beta.8` lists every change
(PRs #187, #188 and #189): Media Manager reads each indexer's list of newest
uploads and brings a matching waiting title's own search forward; a search
request may ask for up to 500 results where the indexer gives them
(**Resultater pr. svar**); searches follow the indexer's stated total over up
to three pages; the same release on several indexers is tried on the most
reliable one first; background searches may use 60 % of an indexer's daily
search limit; and releases an indexer marks as a bad or password-protected
archive are tried last.

The rules for checking language and quality did not change, and files are
still measured after download. The newest-uploads list never selects or
downloads anything, and it never opens a new round of attempts: it only brings
forward the search (or the paced look for releases) the title already had.
Newznab pacing, cooldowns, redirect pinning and secret sanitization are
unchanged; the reader keeps itself to a tenth of an indexer's query limit with
every page counted.

## Installation and upgrade

Use [../operations/install-release.md](../operations/install-release.md) with:

```sh
MEDIA_MANAGER_API_IMAGE=ghcr.io/media-manager52/media-manager-api@sha256:8f635c43bc77adfa2f72a7f83026317111060dbbbc8d586830c64c5aeb10f466
MEDIA_MANAGER_UI_IMAGE=ghcr.io/media-manager52/media-manager-ui@sha256:b70000dd80b28f9dcac464eec3dfc4d1acad902e0c091249f93951e34b750410
MEDIA_MANAGER_VERSION=0.1.0-beta.8
MEDIA_MANAGER_COMMIT=94010c112bf288a6532341cb36c36a23aa5fc4e4
```

Upgrading from `v0.1.0-beta.7` runs migration 0058, which adds the two tables
the newest-uploads reader uses (`indexer_feed_state` and
`indexer_feed_matches`) and changes no existing table. Create an encrypted
backup first as usual. A rollback starts the `v0.1.0-beta.7` image pair; the
two new tables are then unused. `FEED_WATCH=off` switches the reader off
without a rollback.

## Verification

- **CI:** the runs in the identity table.
- **Production:** the owner's library runs this commit (schema 58). The API
  answered ready after the deploy. In the first hours every enabled Newznab
  indexer's newest uploads were read without a failure, the read intervals
  moved between 400 and 1,200 seconds with the share of new uploads, matches
  were recorded for waiting titles, searches kept completing, and the server
  log showed no panic or error line. The error log held only ordinary download
  results (releases rejected for missing subtitles or incomplete articles).
- **Security:** zero open Dependabot alerts and `npm audit --omit=dev` reports
  zero vulnerabilities at tagging time.

## Known limitations

- `linux/amd64` only; ARM64 is not built.
- Reading newest uploads had run for only a few hours on the production
  library at tagging time. How many titles it catches over time has not been
  measured.
- The repeated searches for waiting titles have not been reduced; the reading
  comes on top of them.
- Most matches so far were for titles whose round of attempts is used up.
  Such a title does not get a new round by itself, even when a new upload
  fits; the owner still opens it.
- Indexers that are not Newznab are not read.
- A larger page size was observed on three indexers only; the others answer
  with 100 results whatever is asked for.
- **Fejllog** shows failures stored in the database, not the server's own
  process log.
- A Danish name does not count as proof of Danish audio. A DANiSH release with
  untagged audio is rejected in libraries that require Danish audio.
- Danish releases that do not state Danish in the name and have no series ID
  are still held.
- **Overtag bibliotek** and resuming an interrupted **Flyt** are covered by
  automated tests but have not been used on real titles.
- No installation on a genuinely clean third-party host has been recorded.
- Off-site backup is not built in.
- Restore is documented and operator-run, not automated.
- The web UI is Danish only.
- Only the supported stack (Seerr, Media Manager, Newznab, AltMount, Plex) is
  tested.
