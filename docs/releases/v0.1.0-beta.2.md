## What changed since v0.1.0-beta.1

The [changelog](../../CHANGELOG.md) section `0.1.0-beta.2` lists every change
(PRs #124–#131). In short:

- Setup from scratch on the website: the **Kom i gang** checklist
  (`GET /api/v1/setup/status`), connection forms with a connection test,
  indexer creation and commissioning, library roots from a Plex library,
  quality profiles from a preset, and notification destinations.
- Connection secrets entered on the website are stored AES-256-GCM encrypted
  (migration 55) under `SECRET_ENCRYPTION_KEY`; environment references keep
  working.
- Seerr intake from the website's Seerr connection when no `SEERR_*` values are
  set, and a webhook setup that saves only after Seerr's test reached the API.
- Standard and 4K editions (migration 54), with `/radarr4k` and `/sonarr4k`.
- Self-repair of files AltMount removed (migration 52), owner-requested
  replacements (migration 53), and unplayable output treated as a release
  failure.

## Installation and upgrade

Use [../operations/install-release.md](../operations/install-release.md) with:

```sh
MEDIA_MANAGER_API_IMAGE=ghcr.io/media-manager52/media-manager-api@sha256:ed9e3685149bbc15cdf26907bacac1bbb81ae04a07df47a326ce24e69c515d49
MEDIA_MANAGER_UI_IMAGE=ghcr.io/media-manager52/media-manager-ui@sha256:ef131754a741a80edc311d823495b6830d273062c975cf6489811f9d80f7136d
MEDIA_MANAGER_VERSION=0.1.0-beta.2
MEDIA_MANAGER_COMMIT=bb24c654a6c881a896f863bf24a88962312d5aec
```

Upgrading from `v0.1.0-beta.1` migrates schema 51 to 55 at API start. Create an
encrypted backup first. To store secrets from the website, set
`SECRET_ENCRYPTION_KEY` (64 hex characters or a passphrase of at least 32
characters); without it, an existing `OLDBOYS_CREDENTIAL_ENCRYPTION_KEY` is used,
and without either, the website refuses to store secrets instead of storing them
in plaintext. Back up the key with the database backup key: secrets stored
under it cannot be read without it. A rollback restores the pre-upgrade
database into a fresh database and starts the `v0.1.0-beta.1` image pair; never
run an older image against a newer schema.

## Verification

- **CI** on the exact commit: run 41899330575, all five jobs.
- **Production:** the owner's library runs this commit (schema 55); the setup
  checklist reports every required step done and Seerr's webhook is confirmed
  to send Media Manager's events with the configured secret. One real 4K movie
  was requested, verified as 2160p and confirmed by Plex in the 4K library.
- **Website setup:** browser tests cover adding Plex (create → encrypted secret
  → check), adding a 4K root from a Plex library and the checklist; Go
  integration tests cover encrypted secrets, connection checks against fake
  Plex/Seerr servers, and the Seerr webhook setup end to end. The pages were
  also viewed read-only against the production API.
- **Security:** zero open Dependabot alerts and `npm audit --omit=dev` reports
  zero vulnerabilities at tagging time.

## Known limitations

- `linux/amd64` only; ARM64 is not built.
- No installation on a genuinely clean third-party host has been recorded, and
  the website setup has not been walked through on a fresh install outside
  automated tests.
- Off-site backup is not built in.
- Restore is documented and operator-run, not automated.
- Seerr saved on the website starts after one API restart; TMDB is still set
  with `TMDB_ACCESS_TOKEN` in `.env`.
- The web UI is Danish only.
- Only the supported stack (Seerr, Media Manager, Newznab, AltMount, Plex) is
  tested.
