## What changed since v0.1.0-beta.10

The [changelog](../../CHANGELOG.md) section `0.1.0-beta.11` lists every change
(PRs #209 to #213). The main themes:

- **MDBList lists** (#209, #210). The new **Lister** page follows public
  mdblist.com lists the way Radarr and Sonarr list imports do: new titles are
  added as with **Tilføj** and searched at once; titles already present or
  removed by the owner are skipped. Addresses with any letters (æ, ø, å) work.
- **Failed AltMount imports retry by themselves** (#211). The same download is
  imported again after 10 minutes, then 1, 4 and 12 hours, paced globally to one
  retry per 90 seconds, without a new NZB request. When the retries are used up
  the release is set aside and the next one is tried.
- **The rest of Kræver handling resolves itself** (#212). Rounds with no untried
  release left wait for a new upload, downloads that cannot be inspected are set
  aside, and timed-out Plex confirmations are asked again after 1, 6 and 24
  hours (at most three times). Only an indexer refusing access (HTTP 401/403)
  still waits for the owner.
- **A hanging Plex cannot stall the queue** (#213). The broken-file check runs
  in its own worker lane, at most one is open at a time, and work that has
  failed five times is claimed after healthy work.

The rules for checking language and quality did not change, and every file is
still measured after download; nothing reaches Plex without inspection. Newznab
pacing, cooldowns, redirect pinning and secret sanitization are unchanged.

## Installation and upgrade

Use [../operations/install-release.md](../operations/install-release.md) with:

```sh
MEDIA_MANAGER_API_IMAGE=ghcr.io/media-manager52/media-manager-api@sha256:9d160b24d52a1be786dc6a910295423ef66a556f55eebc05d518e79e9fc483e5
MEDIA_MANAGER_UI_IMAGE=ghcr.io/media-manager52/media-manager-ui@sha256:d632cc55a2a40b6dbd2135b53672c2c7fc75427bdbfdff4c1442b2985f67288a
MEDIA_MANAGER_VERSION=0.1.0-beta.11
MEDIA_MANAGER_COMMIT=b7a0c69b1886459c7c31c59c573bd48ebbb524a0
```

Upgrading from `v0.1.0-beta.10` runs migrations 0064 to 0067: MDBList import
lists, non-ASCII list addresses, the AltMount automatic-retry columns and the
`import_failed` and `inspection_failed` exclusion kinds. No existing data is
rewritten. Create an encrypted backup first as usual. A rollback starts the
`v0.1.0-beta.10` image pair; the new tables and columns are then unused. Work
already at Kræver handling is picked up automatically, 10 of each kind every
5 minutes.

## Verification

- **CI:** the runs in the identity table.
- **Production:** the owner's library runs this commit (schema 67). After the
  deploys, Kræver handling went from 73 open cases to 0; resumed AltMount
  imports were retried without new NZB requests; the separate broken-file lane
  had no pile-up and the server log showed no error line.
- **Security:** zero open Dependabot alerts and `npm audit --omit=dev` reports
  zero vulnerabilities at tagging time.

## Known limitations

- `linux/amd64` only; ARM64 is not built.
- The effect of the v0.1.0-beta.10 search schedule on the daily query count has
  not been measured over a full day yet; the day it should have been measured
  the queue was stalled for hours by a hanging Plex.
- Every indexer is still asked on every search.
- **Fejllog** shows failures stored in the database, not the server's own
  process log.
- A Danish name does not count as proof of Danish audio. A DANiSH release with
  untagged audio is rejected in libraries that require Danish audio.
- **Overtag bibliotek** and resuming an interrupted **Flyt** are covered by
  automated tests but have not been used on real titles.
- No installation on a genuinely clean third-party host has been recorded.
- Off-site backup is not built in.
- Restore is documented and operator-run, not automated.
- The web UI is Danish only.
- Only the supported stack (Seerr, Media Manager, Newznab, AltMount, Plex) is
  tested.
