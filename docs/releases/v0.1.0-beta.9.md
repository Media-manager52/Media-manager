## What changed since v0.1.0-beta.8

The [changelog](../../CHANGELOG.md) section `0.1.0-beta.9` lists every change
(PRs #191 to #202). The main themes:

- **Far fewer indexer queries.** One search per season instead of one per
  episode, with all episodes of a season asking under the same name within a
  12-hour slot (#199, #201); the search after a failed download picks the next
  release from the search that found the failed one instead of asking every
  indexer again (#202); rescans postponed by pacing wait at least 12 hours
  (#198).
- **Fewer downloads without the required Danish.** Each release group's
  measured Danish record orders releases without a Danish clue and holds groups
  that almost never carry it (#200).
- **Rounds start by themselves** when a new upload or the title's own rescan
  finds a new eligible release (#191, #198).
- **Find manglende** (#192) and the **HolyArrs-style redesign** of every page
  (#193 to #197).
- Go 1.27.4 (GO-2026-6859) and a faster workflow lookup (schema 60).

The rules for checking language and quality did not change, and every file is
still measured after download. Reused answers (season answers, the answers of
the search that found a failed release) are evaluated again under the
workflow's own scope, rules and exclusions and are never reused after a newest-
uploads match or an owner search (invariants S21 and S23). The learned group
record only orders or holds releases; it never makes one eligible (S22).
Newznab pacing, cooldowns, redirect pinning and secret sanitization are
unchanged.

## Installation and upgrade

Use [../operations/install-release.md](../operations/install-release.md) with:

```sh
MEDIA_MANAGER_API_IMAGE=ghcr.io/media-manager52/media-manager-api@sha256:9673a1856fe4f937db30e86e7b5c80afa3fcf73ea1ae32e0fdad790480691f91
MEDIA_MANAGER_UI_IMAGE=ghcr.io/media-manager52/media-manager-ui@sha256:ebf32c62d956f52af994cd24b26c4849ba324f730b720e4ff73fae02f0c04854
MEDIA_MANAGER_VERSION=0.1.0-beta.9
MEDIA_MANAGER_COMMIT=9160aae85642ccdbfc7aaad90722b0539bd7289d
```

Upgrading from `v0.1.0-beta.8` runs migrations 0059 to 0062: one more outcome
for recorded newest-upload matches, the index `workflows_media_variant`, the
column `workflow_retry_discovery.automatic_round_refused_generation`, and the
short-lived tables `season_search_responses` and `search_recent_answers`. No
existing data is rewritten. Create an encrypted backup first as usual. A
rollback starts the `v0.1.0-beta.8` image pair; the new tables, index and
column are then unused. `FEED_OPEN_ROUNDS=off` leaves every new round to the
owner without a rollback.

## Verification

- **CI:** the runs in the identity table.
- **Production:** the owner's library runs this commit (schema 62). The API
  answered ready after each deploy and the server log showed no panic or error
  line. Indexer queries fell from about 3,600 to 4,200 per hour in the morning
  to about 1,800 per hour in the first hour with season search and the shared
  season name; in ten minutes 591 episode searches reused a season answer
  against 120 new season searches. The group record held about 1,000 releases
  in the first 35 minutes, each with its reason shown.
- **Security:** zero open Dependabot alerts and `npm audit --omit=dev` reports
  zero vulnerabilities at tagging time.

## Known limitations

- `linux/amd64` only; ARM64 is not built.
- Season search, reuse after a failed download and the group record had run for
  only a few hours on the production library at tagging time. A full day has
  not been measured, and reuse after a failed download had not yet been seen
  live.
- Every indexer is still asked on every search; indexers that rarely add a
  usable release are not yet asked less often.
- A held group stays held until new measurements say otherwise, and new
  measurements only come from its releases that are still tried.
- **Fejllog** shows failures stored in the database, not the server's own
  process log.
- A Danish name does not count as proof of Danish audio. A DANiSH release with
  untagged audio is rejected in libraries that require Danish audio.
- **Overtag bibliotek** and resuming an interrupted **Flyt** are covered by
  automated tests but have not been used on real titles.
- No installation on a genuinely clean third-party host has been recorded.
- Off-site backup is not built in.
- Restore is documented and operator-run, not automated.
- The web UI is Danish only.
- Only the supported stack (Seerr, Media Manager, Newznab, AltMount, Plex) is
  tested.
