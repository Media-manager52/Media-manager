## Installation

Use [../operations/install-release.md](../operations/install-release.md). The
release Compose file installs published API/UI images without a local build and
fails closed when either immutable image variable is missing. Do not use `main`
or `latest` for a release installation.

The host needs Docker Engine, Compose v2.24 or later, PostgreSQL storage, movie
and TV directories, an AltMount parent mount, and a shared Docker network for
AltMount/Plex/Seerr. Plex, AltMount, and at least one Newznab indexer are
required for acquisition; Seerr and metadata providers are optional.

## First-run configuration

1. Run `./scripts/setup-cosmos.sh --no-start`, set the two immutable image
   references, then start with `compose.release.yaml`.
2. Add AltMount and Plex under **Settings → Connections**; commission a Newznab
   indexer under **Sources → Indexers**.
3. Create movie/TV library roots under **Settings → Storage** and quality and
   language profiles under **Settings → Profiles**. Danish is never assumed;
   the owner chooses required/preferred languages explicitly.
4. Add a title under **Discover**. The screen names missing prerequisites instead
   of starting an unsafe workflow.
5. Open **Wanted**, **Workflows**, **Files**, and **Requests** to inspect the
   first run. Evidence and failure details remain visible; retries are bounded.

## Backup and restore

Create an encrypted, restore-verified backup in **System → Backups** and keep
`BACKUP_ENCRYPTION_KEY` separately from the backup. The exact decryption and
fresh-database restore sequence is in
[../operations/runbook.md](../operations/runbook.md). A disposable restore test
was performed; off-site backup still requires an owner-supplied destination and
a restore drill.

## Upgrade path

Install a newer immutable image pair with the same `COMPOSE_PROJECT_NAME` and
environment files. Migrations run transactionally at API startup. Back up first;
schema changes are forward-only. A rollback requires restoring the pre-upgrade
database to a fresh database and starting the previous image pair. Never run a
schema-49 image against a migrated schema-50 database.

## Security notes

- Cosmos Cloud is the only supported public edge. Keep the API port loopback-only.
- The Cosmos `/api` route injects the owner bearer token server-side; the UI,
  `/api`, and `/health` routes must use one explicit hostname and owner-only
  access.
- The API and UI run as non-root users; the AltMount parent is read-only and uses
  shared propagation. Do not edit or delete AltMount files through Media Manager.
- Dependency audit is zero on the release source. The UI image still contains
  dev/build tooling; it is not exposed by the application but should be pruned
  post-beta.
- No release may silently accept a known critical security issue. See
  [../status/release-v0.1.0-beta.md](../status/release-v0.1.0-beta.md).

## Acceptance evidence

- Clean disposable Compose install from immutable images, owner authentication,
  PostgreSQL initialization, read-only AltMount parent, writable libraries, and
  restart persistence passed.
- Encrypted backup creation, isolated verification, authenticated download,
  atomic decryption, and restore into a fresh PostgreSQL/API/UI stack passed;
  truncated input was rejected without a plaintext dump.
- Search/selection, retrieval, publication, symlink and Plex-confirmation tests
  pass in isolated PostgreSQL and temporary filesystems.
- **Not verified:** a continuous real AltMount/Plex/Seerr journey, a real Cosmos
  wizard install, a FUSE child remount, off-site restore, or a clean public host.
  These remain release gates, not claims.

## Known limitations

- `linux/amd64` only; ARM64 is post-beta.
- No production restore automation; restore is documented and operator-run.
- Off-site backup requires owner credentials and a tested destination.
- The UI contains dev/build dependencies in the runtime image.
- Large-list pagination is bounded and visible; keyset pagination is post-beta.
- Direct IMDb metadata enrichment is unavailable without a separately licensed
  source.
- The Cosmos store listing PR is maintained upstream; local listing text is
  corrected, but acceptance of the upstream listing is outside this repository.

## Publication gate

Do not create the `v0.1.0-beta.1` tag or publish images/release notes until:

1. The final `main` commit has a successful Verify run on the exact commit.
2. The Cosmos route host/owner-authorization acceptance is recorded (or the
   remaining manual gate is explicitly accepted by the owner).
3. Off-site backup is configured or explicitly deferred with risk acceptance.
4. The real or faithfully simulated end-to-end acceptance result is recorded.
5. The owner approves release publication separately from merge approval.
