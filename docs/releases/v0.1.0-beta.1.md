## Backup, restore and upgrade

Create an encrypted, restore-verified backup in **System → Backup** and keep
`BACKUP_ENCRYPTION_KEY` separately from the backup. The decryption and
fresh-database restore sequence is in
[../operations/runbook.md](../operations/runbook.md). Migrations run
transactionally and forward-only at API startup; back up first. A rollback
restores the pre-upgrade database into a fresh database and starts the previous
image pair. Never run an older image against a newer schema.

## Security notes

- Cosmos Cloud is the only supported public edge. Keep the API port loopback-only.
- The Cosmos `/api` route injects the owner bearer token server-side; the UI,
  `/api` and `/health` routes use one explicit host and owner-only access.
- Streaming clients use a separate player token that can only search for and
  play releases; it cannot read workflows, settings or backups.
- The API and UI run as non-root users. The AltMount parent is mounted
  read-only with `rslave` propagation. Media Manager never edits or deletes
  AltMount files.
- The UI image contains only the built files and a dependency-free Node server.
- Dependency audit: `npm audit` gate in CI. One open Dependabot advisory
  (minimatch, development-only lint tooling, not in any image) was dismissed as
  tolerable risk on 2026-11-04 with its reason recorded on the alert.

The candidate note listed six gates. Each was closed as follows:

1. **Verify on the exact commit:** run 41751270399 passed all five jobs on

2. **Cosmos route host/owner authorization:** recorded by the live disposable
   Cosmos install on 2026-10-26 ([../../deploy/cosmos/VERIFICATION.md](../../deploy/cosmos/VERIFICATION.md), result PASS).
3. **Off-site backup:** explicitly deferred by the owner; listed below as a
   known limitation.
4. **End-to-end acceptance:** the same code runs the owner's production library
   with real Seerr requests, nine Newznab indexers plus OldBoys, AltMount and
   Plex. Production was deployed from this exact commit on 2026-11-04.
5. **Image licensing:** both published images carry
   `org.opencontainers.image.licenses="AGPL-3.0-only"` and contain
   `/usr/share/doc/media-manager/LICENSE` and `THIRD_PARTY_NOTICES.md`,
   byte-identical to the tagged source (SHA-256 checked).
6. **Owner approval:** given on 2026-11-04.

## Known limitations

- `linux/amd64` only; ARM64 is not built.
- No installation on a genuinely clean third-party host has been recorded; the
  verified installs ran on the owner's server.
- Off-site backup is not built in. Backups land on the same disk as the
  database; copy them elsewhere.
- Restore is documented and operator-run, not automated.
- The web UI is Danish only.
- Direct IMDb metadata enrichment needs a separately licensed source.
- Only the supported stack (Seerr, Media Manager, Newznab, AltMount, Plex) is
  tested.
