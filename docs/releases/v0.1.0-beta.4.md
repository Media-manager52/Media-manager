MEDIA_MANAGER_COMMIT=f928173a21e9045016783f56820e1a6fd06fbc81

Upgrading from `v0.1.0-beta.3` runs no migration, because the schema is 57 in
both. Create an encrypted backup first as usual. A rollback starts the
`v0.1.0-beta.3` image pair.

## Known limitations

- `linux/amd64` only; ARM64 is not built.
- A Danish name does not count as proof of Danish audio. A DANiSH release with
  untagged audio is rejected in libraries that require Danish audio.
- Danish releases that do not state Danish in the name and have no series ID
  are still held.
- How many releases these fixes recover was not yet measured at tagging time.
- **Overtag bibliotek** and resuming an interrupted **Flyt** are covered by
  automated tests but have not been used on real titles.
- No installation on a genuinely clean third-party host has been recorded.
- Off-site backup is not built in.
- Restore is documented and operator-run, not automated.
- The web UI is Danish only.
- Only the supported stack (Seerr, Media Manager, Newznab, AltMount, Plex) is
  tested.
