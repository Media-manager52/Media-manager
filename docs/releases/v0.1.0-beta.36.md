## What changed since v0.1.0-beta.35

The [changelog](../../CHANGELOG.md) section `0.1.0-beta.36` lists the changes
(PR #272): abNZB's newest uploads are read as one movie and one series
request, the usage counters an indexer states can only tighten Media Manager's
own request reservations, and every background event records its scheduled
wait, queue wait, work and retry delay. Release selection, language and
quality rules, ranking and exclusions are unchanged.

## Installation and upgrade

Use [../operations/install-release.md](../operations/install-release.md) with:

```sh
MEDIA_MANAGER_API_IMAGE=ghcr.io/media-manager52/media-manager-api@sha256:3270016a16157e2e3e739f0f25f7525a90aa4822e4b2a68525cb88cafdcac331
MEDIA_MANAGER_UI_IMAGE=ghcr.io/media-manager52/media-manager-ui@sha256:7ed9c9126643456b086edcf79bd3fe1646a64cb0739e7d2e6770b6421ea42121
MEDIA_MANAGER_VERSION=0.1.0-beta.36
MEDIA_MANAGER_COMMIT=ee9654240ea42bcbf8930f8ac32741edc9556276
```

Upgrading from `v0.1.0-beta.35` runs migration 0071 (schema 71), which adds the
tables `indexer_feed_stream_state` and `indexer_provider_limits` and six timing
columns on `outbox_events`. Nothing existing is altered or deleted. Create an
encrypted backup first as usual. `FEED_SPLIT=off` and
`INDEXER_STATED_LIMITS=off` switch the two behaviour changes off without a
downgrade. A rollback starts the `v0.1.0-beta.35` image pair on a database
restored from the backup taken before the upgrade: the older version does not
report ready on schema 71.
