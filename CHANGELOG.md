# Changelog

Notable Media Manager changes are recorded here. The structure follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and versions use [semantic versioning](https://semver.org/). Each release is a Git tag with a [GitHub release](https://github.com/Media-manager52/Media-manager/releases) that records its image digests.

## Unreleased

### Fixed

- **A backup interrupted by a restart no longer blocks every later attempt.** The restore check uses a test database named after the backup. A restart during that check left the database behind, so each retry made the whole backup again and then failed with "verification database creation failed". A new attempt now removes that leftover test database first, and removes temporary backup files older than 3 hours (including a decrypted copy of the database) that a killed attempt left behind.

### Removed

- **Code the program never runs is gone.** About twenty functions and one file that only tests still called were removed: old Newznab search and download shortcuts, an unused season-pack job state machine, unused naming, link and AltMount session helpers, two leftover commissioning helpers and an unused web helper. Their tests now exercise the functions Media Manager actually uses, so the same safety checks (download redirects, link containment, NZB validation, pack coverage) still run. The season workflow name is now built in one place. No behaviour changes.
- **Search capability profiles are removed (schema 70).** Only the removed commissioning v2 could activate a profile, so every search already used the dialect the normal commission check stored. The search planner, the profile store code and about 1,000 lines of profile validation are gone, and migration 0070 drops the profile and operation status tables (they held only empty drafts) and refuses to run if a profile was ever activated. Searches send the same requests as before, each indexer in a search makes one database read less, and searches waiting for a retry keep their stored intent.
- **Two dated status logs are gone.** `docs/status/implementation.md` (a feature audit from September) and `docs/status/release.md` (a running log that repeated this changelog) were removed; they remain in the Git history. The changelog and `docs/releases/` are the record of what changed.

## [0.1.0-beta.22] - 2026-11-13

### Removed

- **Stale documentation and unused code are gone.** Old AI session prompts, superseded design proposals, dated status snapshots and a one-time handoff note were removed from `docs/` (they remain in the Git history), and an unused AltMount cancel-and-delete client path was dropped. No behaviour changes.
- **Indexer commissioning v2 is removed (schema 69).** The owner-authorized multi-step commissioning runs were never used: their nine `/commissioning-v2/` routes, the `COMMISSIONING_V2_OWNER_ORIGIN` setting, the run and step tables and the unresolved-attempt gate on indexer pacing are gone. The migration refuses to run if any v2 run or step was ever recorded. Adding an indexer still uses the normal commission check, indexer pacing and quotas are unchanged, and each search no longer makes an extra database read for the gate.

## [0.1.0-beta.21] - 2026-11-12

### Security

- **A connection can no longer use one of the server's own secrets.** A connection that named the owner token, the database URL, a backup or encryption key, the Servarr key or the Seerr webhook secret as its secret reference would have that value sent to the connection's address by a connection check. Such references are now refused and never resolved; backups read their key directly.
- **A Prowlarr backup upload no longer returns the indexer API keys it found** (invariant S18).
- **Hiding a credential in a support text is safe with any characters.** A non-ASCII character before a marker such as `api_key=` could keep the start of the secret or crash the error log.

### Fixed

- **A handler that hangs again and again is moved behind healthy work** instead of being picked first every time.
- **Backup downloads are no longer cut off after 60 seconds.**
- **Work that is simply running is no longer shown as "retrying"** on the overview, the queue, the task list and the problem feed.
- **The title page knows each workflow's library folder, profile and allowed actions again.** Flyt, Hent and the other buttons on a title now work from the real workflow instead of guessing.
- **A cancelled duplicate season pack no longer hides the active one** on the title page, and the pack badge shows the same state as the rest of the app.
- **The calendar asks only for the last week and what is coming**, so a long history no longer pushes upcoming episodes out of the list.
- **A required resolution is now checked on the downloaded file, not only on the release name.** A release named 1080p whose picture really measures 720p fails under a profile that requires 1080p, and another release is tried. Preferred resolutions and unknown measurements are unchanged.

## [0.1.0-beta.20] - 2026-11-12

### Fixed

- **Deleting a title also moves its subtitle links to the recycle bin.** A deleted title's Danish `.srt` link stayed in the Plex folder; it now leaves with the video and comes back with it on restore. Restoring an adopted file also removes the replacement's subtitle links.
- **Archive and move wait until Plex has confirmed a title.** A link already in the library but not yet confirmed by Plex was left behind by archive and by a move. Both are now refused until Plex confirms (Slet still recycles such a link).
- **A move to a library of the wrong kind is refused at once** instead of leaving an unfinished move that blocked every later move of the title. A move also waits for an AltMount submission whose outcome is still unknown.
- **The import scan never offers files in the recycle bin**, and a second video in the same folder is no longer treated as a companion of the first.
- **An indexer whose API key was saved on the website can be commissioned** (schema 68); its endpoint fingerprint was empty before.
- **Recommended setup never makes a 4K-only Plex folder the standard default library.**
- **A Seerr series request that names no seasons asks the owner** instead of being shown as already available.
- **IMDb CSV files saved with a byte order mark import normally.**

## [0.1.0-beta.19] - 2026-11-12

### Fixed

- **A commentary or audio-description track no longer counts as the film's language.** A Danish subtitle titled "Commentary", a Danish commentary audio track or a `Movie.da.commentary.srt` sidecar satisfied a required Danish subtitle or Danish audio. Tracks and sidecars marked as commentary, audio description or synstolkning are now ignored as language evidence.
- **A quality profile whose policy is `null` is refused** with a normal validation error instead of crashing the request.

## [0.1.0-beta.18] - 2026-11-12

### Fixed

- **A subtitle for a sample or trailer no longer counts as the film's subtitle.** A file such as `Movie.sample.da.srt` next to `Movie.mkv` satisfied a required Danish subtitle and was published as the film's subtitle. Subtitles that name themselves a sample, trailer, extra or bonus are now ignored.
- **Deleting a title also recycles a link whose Plex confirmation never finished.** After a Plex confirmation timed out and the workflow was cancelled, deleting the title archived it as unpublished and left its link in the library. Such a link is now moved to the recycle folder like any published link.

## [0.1.0-beta.17] - 2026-11-12

### Fixed

- **A cancelled title stays cancelled.** If the owner cancelled a title while its download was still being checked, and the check then failed, the title was put back to waiting and searched again. A failure recorded after cancellation is now ignored.
- **Reviving old archive rejections no longer leaves a gap in the round's download slots.** The remaining downloads are renumbered, so the next download in that round gets a free slot instead of failing after its NZB was already fetched, again on every retry.

## [0.1.0-beta.16] - 2026-11-12

### Fixed

- **A repair no longer rides on a download for another library.** When a broken or audio-less file was repaired while the same film or episode was already being downloaded for a different library (or, for a missing-audio upgrade, with a profile that does not require that audio), the repair joined that download. Its confirmation could then remove the old file's link from its own library, for example a children's library, with the replacement placed elsewhere. Such a repair now waits until that download has finished and then opens its own.
- **A film whose title says "Samples" can be published.** Verification and publication now use the same sample rule, so a verified release of a film like *Free Samples* is no longer stuck as "not exactly one playable file".

## [0.1.0-beta.15] - 2026-11-12

### Fixed

- **A malformed number from MDBList is no longer read as an id or year.** A TVDB id such as `770001wrong` or a year such as `2024.5` became `770001` and `2024`, which could make a list title look like an unrelated series that is already in the library. Anything but a whole positive number is now ignored.

### Tests

- Fourteen new automated tests (written with OpenAI Codex, reviewed before merging) for list intake failures, AltMount upload retries and uncertain answers, indexer pacing after cancellations and budget errors, Plex identities used for confirmation, and subtitle/language policy checks.

## [0.1.0-beta.14] - 2026-11-12

### Fixed

Ten problems found by an automated code review of search, indexer pacing and downloading:

- **A download that could not reach AltMount no longer fetches the NZB again on every retry.** After AltMount could not be reached, the next attempt checks AltMount first and waits 5 minutes while it is down, so no extra indexer grabs are spent.
- **An indexer's Retry-After is bounded.** A very long wait (for example a year) is capped at the indexer's maximum backoff, and `Retry-After: 0` uses the normal backoff instead of no pause.
- **An indexer that keeps failing no longer makes titles search every 30 minutes for good.** After three quick retries of an incomplete search in a row, the next search follows the normal schedule; a complete search starts the count again.
- **New uploads are not starved by titles waiting for their own retry.** Titles whose unfinished search waits for its short retry no longer take the places of each pass over matched new uploads.
- **A search is only counted as complete when the indexer's stated total agrees.** A later page that repeats earlier results while the total says more remain now counts as incomplete, so a season answer is not shared from it.
- **An episode's next search asks the indexer.** An episode no longer answers its own later searches from the season answer it already used.
- **New uploads without an ID no longer stop the catch-up read early.** Only uploads with an ID decide whether a page reached uploads seen before.
- **Episodes that reuse a season answer keep the facts derived from the title.** The candidate now points at an observation with the facts its own evaluation used (source, episode numbering), as a fresh episode search would.
- **A held release returned again by a search is evaluated once.** It is no longer also re-scored from its stored copy in the same search.
- **HDR is recognised from whole words only.** "HDRip" is no longer taken as HDR, and "DV" between dots is recognised as Dolby Vision.
- **The remaining stored detail texts are cut on whole characters.**

## [0.1.0-beta.13] - 2026-11-12

### Fixed

Ten problems found by an automated code review of the language checks, publication and automatic recovery:

- **A re-check of a kept download applies the full language rules.** Re-checking a download kept for review used only its subtitle requirement, so a release that had failed for missing Danish audio could pass on subtitles alone and be published. It now uses the same policy as the first inspection, Danish audio included.
- **A publication interrupted after its first step finishes.** Preparing and starting a publication each move the workflow on, so a retry after a later step failed was ignored and the title stayed in "verifying" or "publishing" for good. The retry now continues the same publication; every step is safe to repeat.
- **A briefly unreadable AltMount mount or library folder no longer fails a publication.** It is tried again after 5 minutes instead of being marked failed for good.
- **No more endless retries.** Re-checking a kept download that can no longer be inspected (no video track, invalid or zero-filled file) now stops with a clear reason, and a download deleted from AltMount's queue while still queued moves on to the next release instead of being read again forever.
- **Languages other than Danish match their usual track tags.** A profile requiring `en`, `sv` or `no` now matches tracks tagged `eng`, `swe` or `nor` (and the other common three-letter codes).
- **A film with "Samples" in its name is no longer treated as a sample.** Only a folder named Sample(s) or "sample" as a word in the file name marks a sample, so a title like Free Samples can be verified.
- **Two subtitle files with the same language no longer fail a publication.** When a release has, for example, `Movie.da.srt` and `Movie.dan.srt`, one of them is published instead of the whole publication failing on the shared Plex name.
- **Long error texts with æ, ø or å are stored.** Texts were cut to their limit by bytes, which could split a Danish letter so the database refused the write on every retry; they are now cut on whole characters.
- **The owner can still retry Plex confirmation after the automatic retries.** The three automatic retries no longer use up the owner's own three.

## [0.1.0-beta.12] - 2026-11-12

### Changed

- **A list no longer fetches titles that are already in Plex.** Titles in Plex that Media Manager did not know (for example from before it was installed) were added again from a followed MDBList list and fetched a second time. Before a title from a list is added, Media Manager now looks it up in your Plex libraries by its TMDB, IMDb or TVDB id; a title Plex already has is left alone and shown as **Fandtes allerede** with "Ligger allerede i Plex". 4K libraries are not counted, so a title kept only in 4K still gets its ordinary copy. If Plex cannot be read, nothing is added and the list is read again an hour later.

## [0.1.0-beta.11] - 2026-11-12

### Added

- **Lister: follow MDBList lists, as in Radarr and Sonarr.** Paste the address of a public list from mdblist.com on the new **Lister** page (no account or key) and choose the film and series library and quality profile, or keep the defaults. Every new title on the list is added exactly as with **Tilføj** and searched at once: films with their TMDB identity, series with every season (specials left out), each season frozen from TMDB's episode list. The profile sets the language and quality requirements as for any other title. Titles you already have are skipped, titles you removed are never added again, and a title that leaves the list stays in the library. Lists are read every 6 hours or with **Læs nu**; the page shows what happened to each title. `POST/PATCH/DELETE /api/v1/import-lists`, `POST /api/v1/import-lists/{id}/sync` and `GET /api/v1/import-lists/{id}/entries`. Schema 64.

### Changed

- **A failed AltMount import no longer waits for you.** When AltMount could not import a download (most often "fast-fail validation inconclusive: context deadline exceeded" while it was busy), the title stopped at **Kræver handling** until you acted; on this server 56 titles waited like that. Media Manager now asks AltMount to import the same download again by itself after 10 minutes, then 1, 4 and 12 hours (twice for other errors), one retry every 90 seconds at most so AltMount is not flooded again. No new NZB is fetched from an indexer for a retry. If it still fails, that release is set aside and the next release is tried, as for any failed download. A message that clearly names a broken release still moves on at once. Titles already waiting are picked up automatically, 10 every 5 minutes. A title waiting for its next retry can still be cancelled or deleted as before. Schema 66.
- **The rest of Kræver handling resolves itself too.** A round where no untried release was left (every remaining release was the same NZB package as one already tried, or its NZB could not be fetched) stopped for you; it now waits for a newly uploaded release and the next round starts by itself, exactly like a round whose attempts are used up. Only an indexer refusing access (HTTP 401/403) still asks you, because the account must be fixed. A download media-info cannot inspect (for example "track codec is unavailable") can never be verified, so that release is set aside and the next one is tried; nothing is ever put in Plex without inspection. A Plex confirmation that timed out is asked again by itself after 1, 6 and 24 hours (at most three times as before). Titles already waiting for you are picked up, 10 of each kind every 5 minutes. Schema 67.

### Fixed

- **A Plex that hangs no longer stops everything else.** Plex stopped answering one night, and the half-hourly check for broken AltMount files, which asks Plex about some files, failed again and again. A new failing check was added every half hour, and because these were the oldest work in the queue the worker spent all its time on them: from early morning no search, download or publication ran for about three and a half hours. The check now runs in its own queue, a new one is not added while the last has not finished, and any work that has already failed five times waits behind healthy work.
- **List addresses with æ, ø or å work.** A MDBList address such as `mdblist.com/lists/søren/julefilm-på-dansk` was refused because only plain letters were accepted. Any letters are now accepted, pasted as they are or percent-encoded (`%C3%A5`), and sent to MDBList encoded exactly once. Slashes, spaces, `?`, `#`, `%` and `.`/`..` are still refused, also by the database (schema 65).

## [0.1.0-beta.10] - 2026-11-11

### Changed

- **A title that found nothing is searched on a schedule, and new uploads do the rest.** A new title that found nothing was searched about six times on its first day (after 30 minutes, then 1, 2, 4, 8 and 16 hours) and every waiting title at least weekly forever, which was most of the daily indexer queries, almost all empty. Of the titles found at all, about 97 % were found within the first three searches. The next search now comes after 30 minutes, 6 hours and a day, then monthly as a safety net (weekly for titles from this or last year). A title whose round is used up is rescanned after a day, a week, then monthly. A fitting new upload seen by the newest-uploads reader still brings the search forward at once, and a search you start yourself is unaffected.
- **The newest-uploads list misses less.** It remembers the uploads it saw last across restarts, so a read after a restart goes on from where the last one stopped instead of starting over. A busy indexer is read up to ten pages back instead of three until the reader reaches uploads it has seen, and a read that still does not reach them is counted as a gap and followed by a quick re-read; **Kilder** shows how many reads had a gap. New episodes waiting for their first scheduled search are now matched too, so an episode uploaded before its search is found at once (one such episode on this server waited two hours). Schema 63.
- **Old wrestling episodes are found by their date.** Episodes of date-named shows (WWE SmackDown, Raw and the like) needed about 65 searches on average before a release was found, because the date search asked with the long catalogue name ("WWE Friday Night SmackDown 2016 12 27") while releases use short names ("WWE.Smackdown.2016.12.27"). An old episode now also asks each indexer the standard way for daily shows, by the series ID and air date without any name, and its text date search uses the title's shortest name. Every answer is still checked under the same identity, date and quality rules.

## [0.1.0-beta.9] - 2026-11-11

### Changed

- **A failed download picks the next release without searching again.** After a release failed (for example no Danish in the download) the title searched every indexer again, on average a few minutes after the search that found it, about 1,600 times a day. It now picks the next release from that search's answers when they are at most two hours old and no new upload or owner search came since; the failed release stays excluded. Schema 62 adds `search_recent_answers`.
- **Releases that almost never have Danish are no longer downloaded to find out.** Nearly half of all downloads ended without the required Danish, and the release group behind a name predicts it well: on this server some groups had Danish in every one of hundreds of downloads, others in almost none. Media Manager now learns each group's record from its own measured downloads (the last 90 days, separately for Danish-audio profiles). Among releases whose name says nothing about Danish, groups that usually have it are tried first, and a group with at least 20 measured downloads and Danish in at most one in twenty is held instead of tried, with the reason shown on the release ("megusta havde dansk i kun 10 af 340 downloads"). Measured on the last week this would have avoided about 390 failed downloads while giving up 19 that succeeded. Releases with any Danish clue and titles originally in Danish are not affected; the Danish requirement itself is unchanged and still verified after every download.
- **Episodes of a season ask with the same name, so they can share one answer.** Episode searches rotate through a title's names one per search, so two episodes of a season usually asked with different names and could not share a season answer. The season search now uses one name per 12 hours for all its episodes and still rotates through the names over time.
- **One search per season instead of one per episode.** About four fifths of all indexer searches went to back-catalogue seasons with many missing episodes, each episode searched on its own on every indexer although the answer to "season N" holds all of them. When a season has at least three missing episodes, the first episode search now asks each indexer for the whole season and the other episodes reuse that answer for 12 hours. Every episode still keeps only its own releases and checks them under its own language and quality rules. A new upload seen by the newest-uploads reader, a search you start yourself, or a season too large to read in full still searches the indexer directly. Schema 61 adds `season_search_responses`.
- **A title whose round is used up starts its next round by itself when its own rescan finds a new release.** Until now only a new upload seen by the newest-uploads reader did that; a release found by the title's daily rescan waited for you to press **Start ny runde** (about 100 titles were waiting like that). It is the same step as your button, under the same rules: unchanged language and quality requirements, the retained-output limit, and at most one automatic round per title per day across both paths. When a rule says no, nothing is written and the same find is not asked again. `FEED_OPEN_ROUNDS=off` still leaves every new round to you.
- **Fewer pointless rescans.** A rescan of a used-up title that some indexers postponed (pacing or daily limit) waited at least two hours before trying the rest again, about 3,500 runs a day that mostly reused saved answers and were postponed again. It now waits at least 12 hours; the newest-uploads reader still brings it forward at once when a fitting upload appears.
- **Go 1.27.4.** The build and CI move from Go 1.27.3 to 1.27.4, which fixes the `net/http` vulnerability GO-2026-6859 reported by `govulncheck`.
- **Bibliotek and Find manglende load faster.** Looking up a title's workflows scanned every workflow ever made once per title; schema 60 adds an index on `workflows (media_id, variant, edition)`.

### Added

- **Find manglende** in **Bibliotek**: one page lists the seasons of your series that Media Manager neither follows nor has in Plex (new seasons after the newest one it knows, and older seasons you never asked for) and the films that have no file and no open work, for example because the work was cancelled. **Tilføj sæson** and **Hent** work exactly as on the title page (same folder and quality profile as the title's own work, the season frozen from TMDB's episode list); new seasons and films can also be added in one click, at most 25 at a time. Older seasons are added one series at a time, since skipping them may have been deliberate. Nothing is fetched before you press. `GET /api/v1/media/gaps` is the read behind it.

### Changed

- **The last pages in the HolyArrs style.** Main buttons are now dark (light in dark mode) across the site, as on HolyArrs; the amber colour stays for links, the logo and highlights. The section tabs on **Indstillinger** and **System** are pills like the other filters. A work page (**Arbejde** › a title) opens with the title's wide picture, the part and its state on it, and a way back to **Arbejde** or the title. **Kilder** gives each indexer a coloured initial, **System** shows each connection with an icon for its kind, and the shortcuts on **Tilføj** get coloured icons. Every button, tab and action is unchanged.

- **Kalender and Arbejde in the HolyArrs style.** **Kalender** shows each day's episodes as pictures with the show's wide artwork, the episode and its state on it; when a show has several episodes of one season on the same day (a season released in one go), they are one picture with the range ("S01E01–E08 · 8 afsnit") and every state is counted on it ("6 I Plex · 2 Venter"), so nothing is hidden. **Arbejde** is a dense list like a download list: a small poster, the title and part, a progress column (AltMount's own percentage as a bar while a download is queued, never an estimate; why work waits on you; when the next search is due), the state with a coloured dot and when it last changed. Tabs, filter and paging are unchanged.

- **Kræver handling and Anmodninger as picture cards.** Each case and each request is now a card with the title's wide picture (or its poster, blurred, when no wide picture is stored), the name and what it concerns on the picture, and the explanation and buttons below, as on HolyArrs' request page. Cases stay grouped by reason with the group buttons, and each card keeps **Detaljer** and every action it had; a long explanation is shortened on the card and shown in full on **Detaljer**. Requests show who asked and when, how far the request has come, and **Godkend**/**Afvis** right on the card (still asking for confirmation before anything is sent to Seerr). Both lists show 18 or 36 cards at a time with **Vis flere**. `GET /api/v1/workflows` and `GET /api/v1/requests` rows now include the title's `poster_url` and `backdrop_url` when metadata is stored.

- **Bibliotek and the title page in the same HolyArrs style.** **Bibliotek** is named after what it shows (**Film**, **Serier** or **Bibliotek**) with the count, the posters get a soft shadow and lift on hover, and a title's status (**Mangler**, **Mangler afsnit**, **Kræver handling**, **Ikke hentet**) is shown with a coloured dot under the poster instead of a label on it. A quiet note above the posters says how many series have new seasons you do not follow and how many films have no file, with a link to **Find manglende** (nothing is added until you choose it there). A title page now opens with the wide picture and the name, tagline, year, length or seasons, age rating and score on it, with the poster beside it on wider screens; below are the buttons, the plot with genres, who directed or created it, who is in it, the channel, the original language and the links, and a row of the cast with their photos. Status, seasons, episodes and files are unchanged. On **Oversigt** the four count cards no longer cut their names short. Every filter, sort, folder choice and action is still there; the Alle/Film/Serier switch on **Bibliotek** is shown on phones and small screens, where the menu with **Film** and **Serier** is folded away.

- **A cleaner look, inspired by HolyArrs.** White pages with soft grey surfaces, calmer text colours and softer shadows (light and dark), adapted from the open-source HolyArrs app (AGPL-3.0-only, see `THIRD_PARTY_NOTICES.md`); Media Manager keeps its amber colour. The menu is now grouped (**Bibliotek** with **Alle titler**, **Film** and **Serier** with their counts and **Find manglende**; **Opgaver**; **Opsætning**) and every existing page is still in it. On a computer the search field sits at the top of every page, and Ctrl+K (⌘K) or `/` jumps to it. **Oversigt** opens with a greeting, big picture tiles for the next episodes and the newest arrival, four count cards with a coloured icon, and **Senest tilføjet** as wide pictures; the lists below are unchanged. `GET /api/v1/media/recent` and `GET /api/v1/calendar` now include each title's `backdrop_url`.

- **Settings and system pages look more finished.** **Biblioteker** groups folders into Film and Serier and shows how many titles each folder holds (with a link to them in **Bibliotek**); row buttons stay aligned when a row has fewer actions; **Backup** opens with three short facts (latest backup, latest restore test, external copy) and folds away old backups whose file is deleted; **Arbejde** explains each empty tab; the indexer cards on **Kilder** line up their small figures; and **Tilføj** shows shortcuts to Find manglende, Seerr requests and taking over an existing library before you search.

- **A new upload can start the next round of attempts by itself.** Until now a title that had used up its round of attempts waited for the owner to press **Start ny runde**, even when a new release had been found for it. When a new upload on an indexer fits such a title and Media Manager's look for releases holds a new, eligible release that has not been tried, the next round now opens without a click. It is the same step as the owner's button and is refused in the same cases: the profile's rules changed since the round, the release was already tried or is excluded, or the limit for kept failed downloads is reached. A title gets at most one such round per 24 hours, each round has the usual number of attempts (`ACQUISITION_ATTEMPTS_PER_ROUND`), and the activity list shows it as done by **Baggrundsarbejde**. Language and quality requirements are applied unchanged, and files are measured after download as always. `FEED_OPEN_ROUNDS=off` in `.env` keeps every new round with the owner. Database schema 59 (one more outcome for recorded matches).

## [0.1.0-beta.8] - 2026-11-10

The eighth public beta: `main` at `94010c1`, database schema 58. Reading each indexer's newest uploads, larger result pages and better use of every indexer (#187, #188, #189). The rules for checking language and quality are unchanged.

### Added

- **Media Manager reads each indexer's list of newest uploads** every 5 to 20 minutes (more often on an indexer where much is uploaded) and compares it with every title that is waiting. When an upload fits a waiting title, that title's own search runs at once instead of at its next scheduled time, so a release is found minutes after it is uploaded. The list itself never selects or downloads anything: the search that follows asks the indexers as always and applies the profile's language and quality requirements unchanged. A title that was searched within the last half hour waits out that half hour first, and a title whose round of attempts is used up gets its paced look for releases brought forward; a new round still needs the owner. Reading uses the indexer's own pacing and at most a tenth of its daily search limit, counting every page of every read; an indexer that cannot list its newest uploads is asked again after an hour, then less often. **Kilder** shows when each indexer's list was last read and how many uploads fitted waiting titles in the last 24 hours (`new_uploads` in `GET /api/v1/indexers`). `FEED_WATCH=off` in `.env` switches the reading off.
- **Resultater pr. svar** on an indexer (**Kilder** → **Rediger**): how many releases one search request asks for, 1 to 500 (`page_limit` in `PATCH /api/v1/settings/integrations/{id}`). Without the setting Media Manager asks for the largest page the indexer advertises, as before.

### Changed

- **Searches follow the indexer's stated number of results.** An indexer that answers with smaller pages than asked for is read on from where its page ended, while its stated total says more remain (still at most three pages and 1,000 releases per indexer and search). Before, a short page always ended the search.
- **Stream lists for players** ask for at most 100 results per indexer, whatever the page size for searches is.

- **The same release on several indexers** is tried on the most reliable indexer first. Reliability is each indexer's share of downloads in the last 30 days that ended as verified files. It only decides between releases with the same score; before, the order between indexers was arbitrary.
- **Background searches may use 60 % of an indexer's daily search limit** instead of 20 %. The rest stays reserved for new requests and searches you start yourself.
- **A full result page is followed by the next page** (at most three pages per indexer and search), so releases beyond the first 100 results are seen.
- **Releases an indexer marks as a bad or password-protected archive** (`password` 2 or 10) are tried last among the usable releases.

The rules for checking language and quality are unchanged.

- **Indexer MediaInfo is read correctly.** Frame sizes are classed by their full width as well as their height, so cinema crops such as `1920x800`, `1910x804` or `3840x1600` count as 1080p/2160p instead of unknown (about 1,300 treasure-maps and msgnews results a day lost their resolution score). MediaInfo codec IDs (`V_MPEG4/ISO/AVC`, `V_MPEGH/ISO/HEVC`, `V_AV1`, `avc1`, `hvc1`) map to the same codecs as release names, which removes treasure-maps' codec conflicts; frame rates drop the `fps` suffix; and treasure-maps' bare `tmdb` attribute is read as the TMDB id (it matched the catalogue in all 13,982 recent results).
- **A failed download is followed by the next good release, not a week's wait.** Each search uses one of the title's names in turn (original, canonical, aliases), and the releases found under one name are rarely returned under the next. After the best release failed, the next search used another name, found nothing and waited, so the other good releases were tried only when the rotation came back to the same name, about a week later (Sons of the Desert had 60 eligible releases and tried one a week). A targeted search now also re-evaluates the eligible releases a provider returned in the last 14 days, with every exclusion, block and attempt check unchanged.
- **A release's list line shows only what held it back.** Under each found release the workflow page showed the first failed rules, including preferences that only rank releases, so a correctly chosen 2160p release read "observed evidence does not satisfy the rule" twice (it did not match the 1080p and 720p preferences). Only failed required rules (and unknown ones on a held release) are shown now, named and in Danish.

- **Episodes are judged by their own runtime.** The check that excludes a video far shorter than expected (a fake, sample or cut-off release) used one runtime for a whole series, so real 12-minute episodes of a show TMDB lists at 30 minutes were excluded as fakes (The Garfield Show), and so were older episodes of shows whose format grew longer. A single-episode workflow is now judged by TMDB's runtime for that exact episode when it is shorter than the series runtime, matched by the episode ID in its frozen snapshot. Because release numbering can differ from TMDB's, the episode runtime only ever relaxes the check, never makes it stricter; without TMDB the series runtime is used as before. Movies and season packs are judged as before.
- **Release files with a colon in their name can be imported.** The path guard refused any file whose name contained a colon as if it were a Windows drive (`C:`), so AltMount output such as `Miraculous:.Tales.of.Ladybug….mkv` was reported as unavailable even though it was there (12 episodes waited in *needs attention*). Only a real drive prefix (a letter followed by a colon) is refused now; every other path check is unchanged.

- A **Problems** page groups owner-actionable conditions instead of making the owner read raw logs: workflows needing attention, retrying worker events, failing integrations, failed backups and off-site copies, notification failures, repairs needing attention, schema/database state and low disk space. The feed is derived from persisted state and disappears when the cause is fixed; it writes nothing.

- Encrypted backups can be copied off the server. The `/system/backups` screen shows the destination, each verified backup's copy state and error, and a retry action. - Self-repair of broken published files. Every 30 minutes Media Manager reads AltMount's list of corrupted files (Usenet articles disappeared, so playback fails). ### Changed

- **More AltMount archive failures now exclude the release and try another candidate.** Clear release-attributable failures such as `no valid files found in RAR archive`, password-protected/listing-less 7z archives, `no valid first 7zip part`, and `incomplete NZB data` are classified as archive/release failures instead of owner-only AltMount attention. Genuine provider/filesystem errors (timeouts, permissions, sockets) still stay infrastructure attention.
- **The owner-attention bell now loads the complete attention read model.** The shell previously loaded only the newest 300 active workflows, so 108 waiting workflows with a ready release never reached the bell. A dedicated `/api/v1/workflows?attention=true` page load now supplies all owner-decision rows; the existing wanted feed still supplies the per-title detail. The bell and sidebar badge therefore agree with `/api/v1/problems` and `/api/v1/dashboard`.
- **An unresponsive AltMount file now becomes visible attention after 24 hours.** `ErrSourceUnresponsive` deferrals keep their durable outbox attempt count instead of being reset, and after 144 ten-minute deferrals the job raises `output_inspection_failed` with an owner-review detail. Ordinary mount/pacing deferrals keep the old reset behaviour so a transient outage does not count as a release or file failure; the queue can now show the retrying unresponsive event.
- **The ID-only dated-release alternate is limited to recent targets.** A date/year-named workflow only drops season/episode filters when its selected air date is within 180 days. Old seasons keep the scoped request, so Raw's 2025/old-season scans no longer spend half their requests fetching and storing hundreds of 2026 candidates that cannot match.
- **A search re-evaluates stored held candidates when a date mapping is available.** Newly available frozen episode facts now re-score existing observations with the same policy, identity, exclusion and upgrade rules, so exact matches observed before the date-mapping fix are no longer held forever just because indexers no longer return them. No provider call or duplicate candidate is created.
- **`/api/v1/wanted` is paged and no longer silently truncates.** It accepts `offset`, validates `limit` 1–500 (default 300), and returns `limit`/`offset` metadata; `limit=5000` now returns `422 invalid_limit` instead of a silent 300-row response.
- **Date/year-named television releases now map from the selected season's frozen snapshot (2026-10-27).** `WorkflowEpisodeNumbering` no longer requires every catalogue season to have a workflow. It still requires every available frozen season to have a distinct air year, and each selected snapshot keeps exact episode keys; preempted gaps are allowed so a dated release such as `WWE.Monday.Night.Raw.2025.07.21...` maps to S33E29 instead of being held as unknown. Fixes long-running daily/weekly shows (Raw has 34 catalogue seasons but only a subset of season workflows) consuming search budget on exact matches. Verified against the production Raw S33E29 workflow.
- **The Problems feed and Dashboard attention count now use one predicate.** `GET /api/v1/problems` includes blocked, quarantined, transport-unknown and waiting-with-ready-discovery workflows, so the feed's workflow counts add up to the Dashboard's `needs_attention` count (205 on 2026-10-27) instead of omitting 108 rows.
- **Workflow listing can be paged and filtered by attention.** `GET /api/v1/workflows` accepts `offset`, `state` and `attention=true`; `attention=true` lists exactly the owner-decision rows behind the Dashboard count. Limits above 500 now return `422 invalid_limit` instead of silently returning 100 rows.
- **An ffprobe timeout is retried, not turned into owner attention.** A probe deadline now returns the existing `ErrSourceUnresponsive` deferral, so the same AltMount job is inspected again later (`altmount_output_unresponsive`) instead of parking the workflow as `output_inspection_failed` for a slow file.
- **The read-only AI inspector is actually restricted to read operations.** It now builds its allowlist from the live OpenAPI `x-mm-effect: read` operations, refuses provider GETs, backup downloads/off-site copies, notification destinations and the Seerr webhook, rejects doubled/encoded separators and dot segments, and never follows upstream redirects. It reloads the owner token after a `401` and fixes file logging in the ES module. Documented with a paste-ready review prompt.
- The Overview date is formatted in UTC on both server and browser. The server previously rendered the previous day while a browser in another timezone rendered the current day, which caused a React hydration error on `/` and prevented the live screen from settling.
- A stopped or unreachable PostgreSQL database now returns `503 database_unavailable` from owner read endpoints instead of a misleading `500`. `/health/ready` already reported the correct 503. The live browser acceptance suite now waits for loading placeholders instead of `networkidle`, because the console intentionally polls persisted state.

- Output inspection now rejects a file that is far shorter than the movie or episode it claims to be. After the existing bounded ffprobe pass, each selected video's duration is compared with the title's TMDB runtime: under half the expected length is a fake, sample or truncated download, so the exact release is excluded as `release_incomplete` and the next candidate is tried. A season pack fails on its short file instead of publishing a broken episode. Unknown runtimes only reject a movie under 10 minutes or an episode under 3 minutes; titles whose expected runtime is under 12 minutes, season-zero specials and files whose duration cannot be read are never judged. No extra probe or provider call is made.

- One stuck task can no longer stop Media Manager's background work. The worker handles one event at a time, and on 2026-10-17 a read blocked inside the AltMount mount (a FUSE read no timeout can interrupt) held it for two hours: no searches, downloads, publications, repairs or Seerr updates. Each handler now runs under a time limit (30 minutes, 3 hours for backups). Past it, the handler is cancelled; if it still does not return within 30 seconds it is abandoned, its event is retried 10 minutes later, and the worker moves on. A panicking handler is retried instead of stopping the process. Opening and sampling a media file for inspection is bounded by the probe timeout: a file that does not answer is inspected again 10 minutes later (`altmount_output_unresponsive`). It is never treated as a bad release, and ffprobe output pipes no longer keep a killed probe waiting.

- Quality profiles can require **audio** languages (`required_audio_languages`, the "Required audio languages" field in Settings → Quality profiles). A profile requiring Danish audio accepts only a Danish dub: subtitles do not count. Release selection holds a release until its name shows Danish audio (`DKaudio`, `DANISH.DUB`, `Dansk.Tale`, or a bare `DANISH`/`DANSK` tag that does not also say subtitles), and output inspection fails any file without a Danish-tagged audio track, so the next release is tried. A tagged audio track in another language beats a name hint. A title made in the required language needs no tag: its releases are accepted and its untagged audio track counts as that language. Seerr's Auto route sends kids titles to a profile requiring Danish audio when one exists.

- Existing files in a library that requires an audio language are upgraded by themselves. The 30-minute repair sweep asks Plex which files lack the language (`audioLanguage!=dan`) and opens an upgrade for each, through the same machinery as broken-file repairs (`GET /api/v1/repairs` now reports `reason` and `retry_after`). The old file keeps playing until Plex confirms the dub. Upgrades are paced: at most 40 search at a time, 10 new per sweep, movies first. One that finds nothing in 7 days is closed as `not_found`, and its file is retried after 60 days. Titles made in the required language are `skipped`, and only AltMount symlinks are ever replaced. Schema 46 adds `reason`, `created_workflow` and `retry_after` to `altmount_repairs`.

- A Seerr request for a season TMDB does not list (for example a newer season only TheTVDB knows) no longer fails its intake forever. Seerr answers HTTP 500 for such a season; intake now skips the lookup, and an actionable season without an episode list is reported as needing attention, naming the season. Request 368 had retried 3,500 times since 2026-10-07.

- A required language (for example Danish) is now satisfied by a subtitle **or an audio track** in that language: a Danish dub needs no Danish subtitles. Output inspection checks audio-track languages next to subtitles, release selection treats explicit Danish-audio names (`DKaudio`, `DANISH.DUB`, `Dansk.Tale`) as positive evidence, and an already published dub is not treated as missing the language when looking for upgrades. A bare `DANISH` tag stays unknown, as before.

- Moving a title to another library (`POST /api/v1/workflows/{id}/relocate-links`) now moves its published subtitle sidecars too (only "verified" ones moved before, so relocated titles lost their Danish subtitles in Plex), keeps the scheduled search of a waiting workflow (relocation bumps the revision and the pending search used to be dropped as stale), and also accepts open workflows that have nothing published yet, so the waiting episodes of a moved series publish into the new library. New `PATCH /api/v1/settings/library-roots/{id}` makes a root the default for its media kind or disables a root that nothing uses any more.

- An AltMount restart or FUSE remount no longer leaves the API with a dead mount. Compose binds the directory containing AltMount's mount point (`ALTMOUNT_HOST_PARENT_PATH`, default `/mnt`) read-only at `/mnt` with `rslave` propagation instead of binding the mount point itself, so a new mount reaches the running API. `ALTMOUNT_HOST_PATH` is no longer used. While the read-only root is unreadable, AltMount reconciles and output inspection wait and retry (`altmount_mount_unavailable`) instead of failing workflows as `altmount_output_unavailable` or `output_inspection_failed`; no release is excluded for a mount outage. System health reports each AltMount output mount, and the Overview tile and sidebar warn when it is unavailable. AltMount companion patches fix the crash behind the 2026-10-06 outage (a race in the AES decrypt reader), keep the mount up when any single FUSE request panics, and add a read-only kernel mount. On 2026-10-06 a dead bind failed 118 workflows over eleven days.

- Acquisition budgets are configurable at startup: one–six attempts per new round (default two) and one–twelve retained failed outputs (default four). Schema 43 widens slot constraints without rewriting historical limits; UI and owner recovery use the configured budgets. Failed outputs, exact exclusions and provider pacing stay enforced.

- The Compose API container explicitly disables IPv6 so indexer requests use the host's IPv4 egress identity even if its external Docker network later enables IPv6. Per-provider pacing, budgets, redirect pinning, and credential boundaries remain unchanged. Other containers and host IPv6 are unaffected.

- The Radarr/Sonarr add and command handlers now accept the real client payloads Seerr sends (`profileId`, `minimumAvailability`, `addOptions`, `searchNow`, `seasons`, `seasonFolder`, `seriesType`, `tags`, `movieIds`, ...). Strict JSON decoding rejected every add with HTTP 400, so Seerr marked new requests FAILED before Media Manager's intake ever saw them.
- Msgnews download locators now request the canonical `www.msgnews.live` host directly. The provider 308-redirects the bare host while carrying the API key in the path, which the cross-origin credential policy correctly rejected; requesting the canonical host keeps the key on the same registrable site without weakening redirect pinning or credential stripping.

### Security

- Every Newznab NZB request, including each of at most two redirects, rechecks the workflow revision and selected candidate immediately before sending.
- Cross-origin NZB redirects use per-hop public-address validation and literal-IP pinning while preserving TLS hostname verification and stripping credentials, Referer, and origin-specific headers.
- Newznab observation URLs are sanitized before persistence, including nested and percent-encoded credential parameters; historical observations were corrected without deleting evidence.
- Secret files, environment files, runtime data, generated output, and deployment credentials remain excluded from version control.
