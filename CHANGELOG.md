# Changelog

Notable Media Manager changes are recorded here. The project has not published a tagged release yet, so the completed work remains under **Unreleased** until the owner cuts the first release.

The structure follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions will use semantic versioning once release tags begin.

## Unreleased

### Added

- Read-only console screens now keep themselves current. Overview, Library, Requests, Wanted, Calendar, component health, tasks, and title pages re-read Media Manager's persisted state every 15 seconds (Workflows every 8), pausing in a background tab and catching up when it is visible again, so download progress and request decisions show without pressing Refresh. Form and settings screens stay manual.
- The Requests page follows Seerr's own state for requests intake saw before approval: "Awaiting approval" while pending (still under Needs attention), "Approved in Seerr" once approved (active, not success, until intake admits it), and "Declined" once declined, which no longer counts as needing attention.
- Owner actions in the console: Approve and Decline for Seerr requests that are still pending there (the decision is made in Seerr, audited, and followed by normal intake; declining asks first), and "Re-check Plex" for titles whose Plex confirmation timed out, which re-queues the existing exact-path confirmation for each of them within its retry limit and never requests a library-wide scan.
- Real download progress and per-episode detail in the owner console. Media Manager now keeps the percentage and stage AltMount reports for the in-flight attempt (schema 42) and shows it as "AltMount 74%"; nothing is estimated, and no percentage is shown when AltMount reports none. TV title pages list every expected episode with its air date and status (acquired, acquiring, needs attention, not yet acquired, unaired), and the Overview core tile shows API uptime from the new `started_at` system-info field.
- An owner-console redesign: a dark indigo palette with the Inter typeface bundled locally, a regrouped sidebar (Overview, Library, Intake, Operations, Sources, Settings, System, Advanced) with search and a live system-status chip, and rebuilt Overview, Movies, TV Shows, title, Wanted, Requests, and Workflows pages. Attention items now explain in plain language what happened, whether Media Manager retries on its own, and what the owner can do; progress is shown as an eight-step stage stepper driven only by persisted state. The backend and API are unchanged.
- A redesigned owner console. Every screen now colours itself through semantic design tokens with a dark (default) and a light theme, selectable per browser as dark, light, or system and applied before first paint. The shell gains an icon-collapsible sidebar with live attention and active-work counts, breadcrumbs, an attention bell that shows its count before opening, and a mobile tab bar; movie and series pages become a hero with Overview, Seasons, Workflows, and Files tabs. Geist fonts are bundled locally, so no font CDN is contacted.
- A browser route tour that visits every route in the dark and light themes and on mobile, asserting no console errors, no unexpected requests, no horizontal overflow, and no serious accessibility violations; GitHub Actions now runs the browser suite alongside GitLab CI.
- Seerr sees a single root folder, `/srv/media/Auto`, from Media Manager's Radarr/Sonarr API. Media Manager routes Auto requests from metadata: kids content to `Børn Film`/`Børn Serier` with the profile that has no required subtitles, documentaries to `Dokumentar`/`Dokumentar Serie`, Christmas titles to `Julefilm`/`Julekalender`, Danish originals to `Danske Film`/`Dansk Tv-Serier`, and everything else to the kind's default root. A missing themed root falls back to the default root; requests carrying an explicit legacy root keep their existing routing.
- A Seerr request for a movie or season that is already Plex-confirmed attaches to the existing workflow and queues the Seerr availability sync instead of downloading it again (delivery outcome `already_available`); mixed requests create workflows only for the missing seasons.
- `POST /api/v1/workflows/{id}/relocate-links` moves a published workflow's current Plex-facing links and verified subtitle companions to another enabled library root of the same media kind, updating `library_links.root_id`, the workflow root, and an audit event (`library.links_relocated`). Link targets and AltMount content are never touched, destinations are never overwritten, and a partially applied move is completed by a rerun. It exists so a movie published into the wrong Plex folder (for example before Seerr root routing existed) can be corrected without re-downloading.
- `POST /api/v1/workflows/{id}/acquisition-rounds/from-known` opens one two-slot round from releases already observed and judged eligible under the profile's current policy, ordered by explicit Danish-subtitle evidence, then a Danish/Nordic title marker, then score, and selects the best known candidate directly. It unblocks the 23 workflows that used both attempts and were waiting for a genuinely new post while untried eligible releases (6 with explicit `da`) sat known.
- `POST /api/v1/workflows/{id}/revive-rejected-archives` revives archive releases the pre-flight screen refused before AltMount ever saw them (60 exclusions), removing their attempt markers, package guards, and exclusion rows with an audit event; queue-time archive failures stay excluded.
- A completed season that is entirely missing but whose searches have only ever observed episode releases (no season pack) now dispatches per-episode acquisition through the existing airing path, because Danish TV is posted per episode. This unblocks Forbrydelser der rystede Danmark, Extreme Makeover, Rivalerne, and Reacher.
- A Radarr/Sonarr-compatible API (`/radarr/api/v3`, `/sonarr/api/v3`, guarded by `SERVARR_API_KEY`) so Seerr can use Media Manager as its only server: it exposes Media Manager's library roots and quality profiles, acknowledges adds without creating a second catalog, and reports Plex-confirmed availability for scans. Existing requests keep working through the Seerr root-folder routes.
- Seerr request routing: the service root folder and profile chosen in Seerr are persisted as request provenance and resolved through owner-created mappings in Settings → Connections; an unmapped folder pauses the request with an exact reason instead of publishing into the wrong library, and saving a mapping requeues paused requests immediately.
- A complete documentation set under `docs/` (onboarding, architecture, operations, reference, status, archive) with an index, package-level Go doc comments for every package, and a `docs:check` link/anchor validator wired into CI.
- A loopback-only authenticated gateway smoke helper that prompts securely without storing the owner password.
- A credential-safe live Playwright acceptance suite for every deployed route across desktop, tablet, and mobile viewports.
- Movie and exact TV season-pack creation acceptance coverage across the live read-only form, browser request payload, owner HTTP API, and isolated PostgreSQL lifecycle.
- A responsive TV Shows library with real series metadata, season-level workflow/file state, filters, selection, and exact series-detail navigation.
- A concise repository code map and local movie-library benchmark for developer and AI-assisted maintenance.
- Owner-only live screens for library, workflows, wanted media, files, sources, settings, health, audit history, adoption review, and release evidence.
- Seerr discovery and intake with exact provider identities and immutable TV-season expectations.
- Provider-aware Newznab commissioning, conservative persisted budgets, request pacing, exact release selection, and Prowlarr backup import.
- AltMount submission, ambiguous-result reconciliation, bounded completed-output inspection, and retained owner-visible failures.
- Complete-season pack acquisition as one job with exact episode coverage.
- Required and preferred subtitle-language policy, canonical Danish `da` normalization, embedded and strict sidecar inspection, and two bounded acquisition attempts.
- Plex-safe managed symlink publication, generation-linked subtitle companions, exact identity/path verification, safe upgrades, and rollback support.
- Direct TMDB, TheTVDB, and Simkl metadata enrichment with persisted provenance.
- Reviewed existing-library adoption, cross-root execution, reversible retention, collections, import lists, notifications, and verified database backups.
- Dense responsive movie library with persisted metadata, real filters, pagination, selected-item inspection, and keyboard operation.
- Local Playwright and axe browser coverage for desktop, mobile, accessibility, interactions, and unexpected-network blocking.
- GitLab CI verification for the frontend, browser suite, and PostgreSQL-backed Go race tests.

### Changed

- Danish subtitles remain **required** for foreign content on the two `Best Available Danish Subs` quality profiles (`required_subtitle_languages: ["da"]`); a same-day experiment that relaxed them to preferred was reverted at owner direction before any relaxed-policy output was verified or published. Output verification enforces the union of the attempt's round snapshot and the profile's current required languages, so a later tightening also applies to a job already in flight. Danish-original routing is unchanged.
- AltMount packages are screened before submission: an NZB whose manifest contains only archive sets, ISO/DVD structures, or other non-playable containers is rejected without an upload. AltMount queue failures caused by archives, unplayable manifests, or missing Usenet segments now exclude the exact release and package and retry another candidate inside the open acquisition round instead of parking the workflow as infrastructure attention. If AltMount has already pruned the failed queue entry, the persisted failure detail drives the same decision instead of retrying the reconcile forever.
- Movie-library assembly now indexes related files, wanted items, and workflows once and reuses precomputed search text, avoiding quadratic work as the catalog grows.
- Catalog loading now retrieves every API page in bounded 200-record batches instead of silently presenting a truncated library.
- Library contrast, typography, responsive sizing, and inspector readability were improved without changing the approved composition.
- Newznab search requests now honor each commissioned provider's supported dialect and independently persisted query/grab budget.
- Equal-score release selection uses deterministic durable identities rather than response timing.
- Indexer cooldown work is deferred without blocking the worker or consuming an acquisition attempt.

### Fixed

- The Calendar lists each episode once. An airing season's episodes are expected by both the season workflow and their own episode workflow, so every episode appeared twice (for example "Waiting" and "Plex confirmed"). The row now shows the most informative workflow: a live one before a cancelled one, a Plex-confirmed one first, then the episode's own workflow.
- The owner can cancel a workflow that needs attention once none of its AltMount jobs is active. The console already offered Cancel for these workflows, but the API refused every one of them with "workflow can no longer be cancelled safely". Pre-retrieval work cancels as before, work that is retrieving, verifying or publishing is still refused, and a cancelled workflow's jobs and retained output stay untouched and owner-visible.
- A Seerr request that Seerr itself marks Completed (status 5, set when it sees the media available through its Plex or *arr scan, or Media Manager's own availability sync) is no longer treated as revoked. Intake previously ran the revocation path for every status except approved, so waiting workflows were cancelled, failed ones were flagged `seerr_request_revoked`, and the Requests page showed the request as "Awaiting approval" under Needs attention. Completed requests are now recorded as `already_available`, their workflows keep their state, and requests recorded by older builds show as Available (Seerr Failed shows as Failed).
- A title page names the quality profile its workflows acquire under before any file exists, instead of "Not assigned" (found in the production upgrade rehearsal).
- Review of the owner-console work: Approve and Decline on the Overview no longer navigate away (the row was a link around the buttons); a downloading workflow shows on the Download step, not Submit; a long non-ASCII AltMount stage label can no longer make PostgreSQL reject the job update; the title page lists only the newest episode expectation, so an episode removed by a correction no longer shows as missing; and "Re-check Plex" can no longer be starved by workflows at their retry limit, and reports real failures as failures instead of skipped items.
- The API process no longer crashes when a Seerr request arrives and any of the optional direct metadata providers (TMDB, TVDB, Simkl) has no credential. The default Compose secrets are empty files, so an unconfigured provider was wired as a nil client and the first metadata enrichment dereferenced it; unconfigured providers now stay unwired and intake falls back to Seerr's TMDB data as intended.
- An owner decision on a Seerr request now stores the status Seerr confirmed straight away, so the request's Approve and Decline buttons disappear as soon as Seerr accepts the decision instead of staying visible until intake re-reads the request. Intake still re-reads it from Seerr.
- The local Playwright web server could not start after the `cloudflare:` loader was added only to the container; it now registers the same loader.
- Seerr routing selects and season progress bars had no accessible names, the overview scrolled horizontally by a few pixels on phones, and native selects with long release titles overflowed their forms.
- Revoking a Seerr request (deleted or no longer approved) now also stops the single-episode workflows dispatched from its season: pre-retrieval episodes are cancelled and retrieving ones need owner attention. Previously only the season workflow was cancelled, and its episodes kept searching and downloading. Episodes of a season another approved request still tracks are kept.
- Seasons acquired episode by episode (airing seasons and Danish TV posted only per episode) now reach Seerr: a season is reported available once every expected episode is Plex-confirmed, and confirmed episodes of an incomplete season mark the media partially available. Previously only a Plex-confirmed season workflow counted, and episode workflows never triggered a sync, so these requests stayed "requested" indefinitely. The 5-minute bootstrap backfills existing confirmed episodes once per media.
- A Seerr request attached to content that was already synced for an earlier request now queues its own availability sync; it previously collided with the earlier sync event for the same workflow revision and was silently dropped.
- Seerr snapshots whose payload changed without a newer `updatedAt` cursor are now accepted instead of failing as a conflict on every poll (36 requests, ~17k deliveries). Approved requests whose current snapshot never produced a workflow are re-evaluated, and polling retries them with a 24-hour backoff.
- The UI container runs the Workers-targeted bundle under Node by resolving `cloudflare:` imports to an inert module (`NODE_OPTIONS=--import=...register-cloudflare-loader.mjs`).
- NZB retrieval failures now select a known eligible alternative within the same open round, bounded to four failed candidates separately from the two download slots. HTTP 401/403 avoids the rejected provider for that round; storage, round, policy and blocklist admission run before a grab. Danish-required searches prefer explicit subtitle evidence, then Danish/Nordic clues, without changing eligibility or output verification. Additive schema 41 does not retry parked requests automatically.

- The package manifest is screened **before** the AltMount submission intent, so a zip/tar/ISO/non-playable rejection excludes the release and queues the next search without creating a job or spending one of the round's two attempt slots (`RecordPreSubmissionRejection`).
- RAR and 7-Zip releases are submitted to AltMount instead of being rejected before upload. AltMount streams stored and nested RAR itself (77 of 84 RAR analyses succeeded in 72 hours, including Media Manager's own DKsubs and NORDiC uploads); the screen had rejected 60 releases, many of them the Danish scene posts being searched for. Archives AltMount cannot stream remain release-attributable failures; zip/tar and ISO/DVD are still rejected.
- A movie release whose provider identity exactly matches the verified IMDb/TMDB identity is no longer held for lacking the metadata year in its title (1,041 held candidates across 23 workflows, all with a matching identity).
- Danish titles are matched and searched in scene spelling (`Forræder` → `Forraeder`, digraph and single-letter folds, `&` as `and`, apostrophes dropped). No title containing æ/ø/å had ever been confirmed; genuine `Forraeder.Under.Kutten...DANiSH` releases were rejected as the wrong title.
- Searches that select nothing back off (30 minutes doubling to 12 hours per round) instead of re-querying all nine indexers every 30 minutes; repeat empty searches had exhausted every indexer's daily query budget.
- A selection whose indexer has exhausted its grab budget moves to the identical release on an indexer with budget left instead of idling until the window resets (44 of 46 pending selections were waiting on one indexer).

- Acquisition selection no longer strands known eligible releases behind a round's novelty cutoff. The selector still prefers releases first observed after the cutoff, but now falls back to any eligible release that was never attempted or excluded instead of parking the workflow as held forever. The submission-intent gate and the duplicate-package fallback apply the same preference. This unblocks 67 open rounds where every eligible candidate (5,154 releases, many with explicit Danish-subtitle evidence) predated a restored cutoff.
- The Radarr/Sonarr add and command handlers now accept the real client payloads Seerr sends (`profileId`, `minimumAvailability`, `addOptions`, `searchNow`, `seasons`, `seasonFolder`, `seriesType`, `tags`, `movieIds`, ...). Strict JSON decoding rejected every add with HTTP 400, so Seerr marked new requests FAILED before Media Manager's intake ever saw them.
- Msgnews download locators now request the canonical `www.msgnews.live` host directly. The provider 308-redirects the bare host while carrying the API key in the path, which the cross-origin credential policy correctly rejected; requesting the canonical host keeps the key on the same registrable site without weakening redirect pinning or credential stripping.

### Security

- Every Newznab NZB request, including each of at most two redirects, rechecks the workflow revision and selected candidate immediately before sending.
- Cross-origin NZB redirects use per-hop public-address validation and literal-IP pinning while preserving TLS hostname verification and stripping credentials, Referer, and origin-specific headers.
- Newznab observation URLs are sanitized before persistence, including nested and percent-encoded credential parameters; historical observations were corrected without deleting evidence.
- Secret files, environment files, runtime data, generated output, and deployment credentials remain excluded from version control.

### Verified

- One real movie workflow and one real complete-season-pack workflow completed exact Danish-subtitle, publication-generation, and Plex identity/path verification.
- A subtitle-failed season output remained unpublished, undeleted, and visible for owner review as required.
- The supported Docker stack, schema 30, production UI build, Go race suite, browser suite, and GitLab pipeline have passing evidence.
