# Changelog

Notable Media Manager changes are recorded here. The project has not published a tagged release yet, so the completed work remains under **Unreleased** until the owner cuts the first release.

The structure follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions will use semantic versioning once release tags begin.

## Unreleased

### Fixed

- **Cosmos routes are host-bound and owner-only.** The `/api`, `/health` and UI routes no longer use `useHost:false`; all three now carry the intended Media Manager hostname and require a Cosmos admin/owner (`AdminOnly:true`). Cosmos 0.23.4 only registers a host matcher when `UseHost` is true, so the previous API and health routes could match on another Cosmos app's hostname; the API route's server-side owner bearer injection would then make the shared API reachable to any signed-in Cosmos user. The API and health paths still take precedence over the UI catch-all on the intended host. A disposable install and cross-host validation remain required before this is treated as live-verified. This changes the install template only; already-installed Cosmos routes, including production, need the same manual `UseHost=true`/`AdminOnly=true` correction before they inherit the fix.

- **Known dependency advisories are patched.** The UI now uses Next.js 16.4.3, Zod 4.6.7, Vite 8.3.5 and the current Cloudflare Vite/Wrangler toolchain, with patched pins for `sharp`, `source-map-js`, `undici` and `fast-uri`. The previous graph had two critical and seven high GitHub advisories; `npm audit` and `npm audit --omit=dev` now report zero. The audit and residual image-optimizer risk are recorded in [`docs/status/dependency-audit-2026-10-30.md`](docs/status/dependency-audit-2026-10-30.md). No API or acquisition behavior changed.

- **Cosmos installs preserve AltMount FUSE propagation and read-only mounting.** The market template keeps the Cosmos-wizard-compatible lowercase volume keys (`type`, `source`, `target`, `readOnly`) and adds `bindOptions.propagation: rslave` on the AltMount parent. Docker's API decoder accepts those keys case-insensitively, while the Cosmos wizard requires lowercase `source`; the previous uppercase `Source` shape crashed the market wizard. The parent bind is read-only and propagation lets an AltMount restart reach the running API. This only protects output that AltMount itself exposes read-only: the owner must enable AltMount's `fuse.read_only` and expose the parent through a shared host mount. A CI static test locks the wizard-compatible shape, propagation, route targets/authentication, writable library mounts, integer healthcheck units and documented amd64 architecture. A live wizard/FUSE-remount check has not yet been performed.

- **Partial searches retry only incomplete indexers.** A budget- or pacing-deferred provider no longer causes every earlier successful provider to be queried again on the next partial attempt. Schema 50 adds `search_partial_retries`, a durable state keyed by workflow, acquisition round, targeted/recovery mode and a full search-intent fingerprint. Completion records both candidate IDs and immutable observation IDs; a candidate whose observation pointer has moved invalidates the chain instead of silently reusing different evidence. Successful empty responses are recorded explicitly. A full/complete search closes the state so a later discovery cycle queries every provider again. An owner search supersedes an older automatic continuation: the continuation cannot reuse completed-provider evidence against a pending owner request. State expires after seven days, the existing hourly maintenance pass removes expired rows, and changes to policy, metadata, episode mapping, query rotation, provider plan/configuration or capability profile invalidate it.

- **Release Intelligence uses candidate last-seen time.** Semantic observation reuse keeps the immutable evidence timestamp at the original poll while `release_candidates.last_observed_at` advances. The release feed now orders by `last_observed_at` (with candidate ID as the tie-breaker), returns both `observed_at` and `last_observed_at`, and labels the UI columns **Last seen** and **Evidence**. Schema 49 adds the matching `release_candidates(last_observed_at DESC,id ASC)` read-model index. The migration runner executes migrations in transactions, so this is a normal transactional index build rather than `CREATE INDEX CONCURRENTLY`; it can briefly block writes during a future deployment.

- **Repeated provider polls reuse semantically unchanged observations.** Search persistence now compares the candidate's current immutable observation with the newly evaluated evidence and ignores only volatile fetch/processing `observed_at` timestamps. Provider raw fields (including publication timestamps), fact values, states, evidence indices, title, operation, parse version and problems still create a new version. `release_candidates.last_observed_at` continues to record freshness, so an unchanged poll does not imply the provider was not checked. This prevents normal polling from growing `release_observations` while preserving held-candidate and OldBoys idempotence, audit history and acquisition behavior.

- **Re-scored held candidates no longer collide on the observation primary key and derived evidence is stable.** A held observation is re-evaluated when a frozen episode mapping becomes available. If its inferred facts changed, persistence tried to insert the existing observation UUID again and PostgreSQL rejected the search transaction. Changed observations now become new immutable `release_observations` versions while the candidate keeps its stable identity and the old evidence remains intact. Episode-numbering and OldBoys binding/range facts are rebuilt deterministically from the original evidence, so repeated unchanged evaluations do not accumulate duplicate derived facts or insert another version; a genuinely changed mapping creates exactly one new version. This fixes the production `release_observations_pkey` retry loop without changing eligibility, language, quality, attempt or publication rules.

### Added

- **Explainable release decisions.** Persisted policy decisions now carry additive `rule_kind`, `category` and `evidence_state` metadata, and the release read models return a deterministic `decision_explanation` with every stored reason and the currently linked observation's evidence. The explanation distinguishes hard requirements, quality preferences, resolution/codec, dynamic range, audio codec, Danish language, identity, upgrade and exclusion reasons. Unknown evidence stays `unknown`; legacy decisions without metadata never have their rule kind guessed; a missing category is derived deterministically from the stored rule and fact names. Verdicts, scores, ranking and selection behavior are unchanged.

- **Evidence explorer labels unrecorded state honestly.** When a candidate has no structured decision evidence, the explorer reads the raw stored facts: a fact array keeps each fact's own state and never produces index-numbered or nameless rows, and the legacy object shape, which stores no state, is shown as "Not recorded" instead of "Unknown".

- **Soft quality-profile presets.** Balanced, Maximum quality, Storage efficient and Compatibility first presets replace only preferred rules for their managed facts. Required rules, scope, identity gates, required languages and unrelated preferences are preserved. Applying a preset uses an expected policy version and a locked policy-only write, so a concurrent profile edit is rejected rather than silently overwritten; existing acquisition rounds keep their snapshotted policy until the owner applies it.

- **Read-only release dry run.** `GET /api/v1/workflows/{id}/candidates/dry-run` replays stored candidates through the same evaluator as the worker, returns the ranked list, best eligible replacement, per-candidate explanation, policy source, provenance and truncation state. It never searches, downloads, submits to AltMount, publishes or changes a block/exclusion. Novelty and final-selection gates are explicitly not re-applied.

- **AGPL-3.0-only licensing.** The owner selected GNU AGPL v3 only. The unmodified license text, SPDX metadata in `package.json`, image license labels and bundled license/notice files, third-party notices, README and Cosmos wording, and owner-console license/source links are now consistent. No third-party component was relicensed; sharp/libvips LGPL notices and bundled font/CSS notices remain in force. The release still requires an owner/legal chain-of-title review because the repository has no CLA or copyright-assignment document.

- **Release installation and encrypted-backup recovery path.** `compose.release.yaml` installs an immutable API/UI image pair without a local source build, and fails closed if either image reference is missing. `media-manager backup-decrypt` validates and decrypts an authenticated `.mmbak` artifact into a PostgreSQL custom dump for the fresh-database restore procedure. Version/image identity, supported platform, schema-50 deployment, license decision and release readiness are documented under `docs/releases`, `docs/operations` and `docs/status`. No release tag has been created.

- **Large owner lists load in explicit server pages.** Workflows, Wanted, managed files and Seerr requests no longer stop at the first 300-record window. The UI starts with a bounded page and offers **Load more** using the exact server offset; the managed-files API now accepts `offset` as well as `limit`, and invalid values return `422` instead of being silently normalized. Append operations deduplicate by the stable workflow/file/request identity, so stable data cannot produce duplicate rows; Wanted adds the workflow ID as a unique tie-breaker for equal state/timestamps. A refresh aborts an in-flight **Load more**, ignores its stale response, and on a failed first page clears the old snapshot and refuses to append against its offset. Wanted fetches exact workflow context for loaded rows outside the first 300-workflow hint, so old attention rows keep their candidate/actions instead of disappearing. Initial page loads stay small, and auto-refresh pauses after the owner has loaded more than one page so a background tick cannot silently discard later pages. Filters, counts and empty-state copy remain scoped to the records currently loaded, and the footer states how many records are loaded and whether more are available. Library joins cap each source at 10,000 records and show a visible partial-view notice with the loaded count rather than failing the whole Movies/Series screen.

- **Read-model indexes (schema 48).** Production-sized `/api/v1/requests` and `/api/v1/intelligence/releases` reads fell from about 15 seconds and 36 seconds to about 0.3 seconds and 0.08 seconds. Schema 48 adds indexes for the newest search run per workflow and for recent release observations/candidates; no API or data semantics change. The existing live acceptance suite now passes all 135 checks against the production data model.

- **Cosmos market distribution.** The publish job now also tags `latest` and makes the public GHCR packages pullable for the Cosmos market. The Media Manager market listing and install template live in [Media-manager52/Media-manager](https://github.com/Media-manager52/Media-manager) (`deploy/cosmos`); its images come from `ghcr.io/media-manager52/media-manager-{api,ui}:latest` in the new GitHub project. The custom source is live now, and the built-in store submission is [PR #336](https://github.com/azukaar/cosmos-servapps-official/pull/336).

- **Cosmos Cloud setup for a new owner.** `./scripts/setup-cosmos.sh` asks for the library folders, AltMount parent, shared Docker network, Cosmos public origin, optional container names, and optional Plex/Newznab/TMDB secrets. It writes mode-600 `.env`/`.env.integrations`, generates the database/owner/backup/OldBoys/Servarr secrets, pins `COMPOSE_PROJECT_NAME=media-manager` so the Cosmos targets `media-manager-api-1`/`media-manager-ui-1` stay valid, creates and joins the shared network, validates Compose, builds and starts the stack, waits for the API, and prints the three Cosmos routes to add. It does not modify Cosmos itself. The friend-facing [`docs/getting-started.md`](docs/getting-started.md) covers the Cosmos edge and routes, AltMount/Plex/indexer/metadata/root/profile setup, folder permissions, updates, backups, security and troubleshooting. `./scripts/make-share-bundle.sh` produces a tracked-source tarball without `.env`, media, runtime data or Git history. The Cosmos-only public architecture and the GitHub VPS deployment remain the supported production path.

- Title pages show the latest workflow's **Search evidence**: each persisted search run, its mode/state, the number of new candidates, and every planned indexer's outcome (succeeded, deferred with the retry time, failed, or not asked) with the safe reason code. It is a read-only view of persisted evidence and never contacts an indexer.

- A **Problems** page groups owner-actionable conditions instead of making the owner read raw logs: workflows needing attention, retrying worker events, failing integrations, failed backups and off-site copies, notification failures, repairs needing attention, schema/database state and low disk space. Repeats collapse to one row with a count and the latest detail; each row links to the owning screen. `GET /api/v1/problems` is the read model. A **Copy for support** / **Download text** bundle includes version, schema, grouped problems, component state, recent backups and queue counts, with token/authorization/password patterns redacted. The feed is derived from persisted state and disappears when the cause is fixed; it writes nothing.

- Encrypted backups can be copied off the server. Set `BACKUP_OFFSITE_KIND` to `s3` (path-style S3-compatible storage) or `webdav`; after the local backup passes its isolated restore verification, Media Manager uploads the already-encrypted `.mmbackup` artifact, never a plaintext dump. The `/system/backups` screen shows the destination, each verified backup's copy state and error, and a retry action. A failed copy leaves the verified local backup intact. `GET /api/v1/backups/{id}/download` falls back to the off-site object when the local file is gone and verifies the recorded size and SHA-256 before serving it. Credentials stay in `.env.integrations` (or `*_FILE`); the destination path is validated against traversal and unsafe characters.

- Self-repair of broken published files. Every 30 minutes Media Manager reads AltMount's list of corrupted files (Usenet articles disappeared, so playback fails). For each one it published, it acquires a replacement for exactly that movie or episode (an episode inside a season pack gets its own episode workflow), rejects the broken release, does not require the replacement to beat the broken file, and retires the broken link once Plex confirms the replacement. Older content (library symlinks Media Manager did not publish, in any folder of a library root's Plex library) is identified through Plex: the title is catalogued from TMDB when unknown, an episode is repaired only when Plex and TMDB agree on its air date, and after confirmation only a symlink that still points at the corrupted file is removed. AltMount content is never modified. `GET /api/v1/repairs` lists repairs (`open`, `repaired`, or `needs_attention` with the reason, for example a file covering several episodes). Schema 45 adds `altmount_repairs`. AltMount's own repair needs Radarr/Sonarr, which this stack does not run.

### Changed

- **More AltMount archive failures now exclude the release and try another candidate.** Clear release-attributable failures such as `no valid files found in RAR archive`, password-protected/listing-less 7z archives, `no valid first 7zip part`, and `incomplete NZB data` are classified as archive/release failures instead of owner-only AltMount attention. Genuine provider/filesystem errors (timeouts, permissions, sockets) still stay infrastructure attention.
- **The owner-attention bell now loads the complete attention read model.** The shell previously loaded only the newest 300 active workflows, so 108 waiting workflows with a ready release never reached the bell. A dedicated `/api/v1/workflows?attention=true` page load now supplies all owner-decision rows; the existing wanted feed still supplies the per-title detail. The bell and sidebar badge therefore agree with `/api/v1/problems` and `/api/v1/dashboard`.
- **An unresponsive AltMount file now becomes visible attention after 24 hours.** `ErrSourceUnresponsive` deferrals keep their durable outbox attempt count instead of being reset, and after 144 ten-minute deferrals the job raises `output_inspection_failed` with an owner-review detail. Ordinary mount/pacing deferrals keep the old reset behaviour so a transient outage does not count as a release or file failure; the queue can now show the retrying unresponsive event.
- **The ID-only dated-release alternate is limited to recent targets.** A date/year-named workflow only drops season/episode filters when its selected air date is within 180 days. Old seasons keep the scoped request, so Raw's 2025/old-season scans no longer spend half their requests fetching and storing hundreds of 2026 candidates that cannot match.
- **A search re-evaluates stored held candidates when a date mapping is available.** Newly available frozen episode facts now re-score existing observations with the same policy, identity, exclusion and upgrade rules, so exact matches observed before the date-mapping fix are no longer held forever just because indexers no longer return them. No provider call or duplicate candidate is created.
- **`/api/v1/wanted` is paged and no longer silently truncates.** It accepts `offset`, validates `limit` 1–500 (default 300), and returns `limit`/`offset` metadata; `limit=5000` now returns `422 invalid_limit` instead of a silent 300-row response.
- **Date/year-named television releases now map from the selected season's frozen snapshot (2026-10-27).** `WorkflowEpisodeNumbering` no longer requires every catalogue season to have a workflow. It still requires every available frozen season to have a distinct air year, and each selected snapshot keeps exact episode keys; preempted gaps are allowed so a dated release such as `WWE.Monday.Night.Raw.2025.07.21...` maps to S33E29 instead of being held as unknown. Fixes long-running daily/weekly shows (Raw has 34 catalogue seasons but only a subset of season workflows) consuming search budget on exact matches. Verified against the production Raw S33E29 workflow.
- **The Problems feed and Dashboard attention count now use one predicate.** `GET /api/v1/problems` includes blocked, quarantined, transport-unknown and waiting-with-ready-discovery workflows, so the feed's workflow counts add up to the Dashboard's `needs_attention` count (205 on 2026-10-27) instead of omitting 108 rows.
- **Workflow listing can be paged and filtered by attention.** `GET /api/v1/workflows` accepts `offset`, `state` and `attention=true`; `attention=true` lists exactly the owner-decision rows behind the Dashboard count. Limits above 500 now return `422 invalid_limit` instead of silently returning 100 rows.
- **An ffprobe timeout is retried, not turned into owner attention.** A probe deadline now returns the existing `ErrSourceUnresponsive` deferral, so the same AltMount job is inspected again later (`altmount_output_unresponsive`) instead of parking the workflow as `output_inspection_failed` for a slow file.
- **The read-only AI inspector is actually restricted to read operations.** It now builds its allowlist from the live OpenAPI `x-mm-effect: read` operations, refuses provider GETs, backup downloads/off-site copies, notification destinations and the Seerr webhook, rejects doubled/encoded separators and dot segments, and never follows upstream redirects. It reloads the owner token after a `401` and fixes file logging in the ES module. Documented with a paste-ready review prompt.
- The Overview date is formatted in UTC on both server and browser. The server previously rendered the previous day while a browser in another timezone rendered the current day, which caused a React hydration error on `/` and prevented the live screen from settling.
- A stopped or unreachable PostgreSQL database now returns `503 database_unavailable` from owner read endpoints instead of a misleading `500`. `/health/ready` already reported the correct 503. The live browser acceptance suite now waits for loading placeholders instead of `networkidle`, because the console intentionally polls persisted state.

- Output inspection now rejects a file that is far shorter than the movie or episode it claims to be. After the existing bounded ffprobe pass, each selected video's duration is compared with the title's TMDB runtime: under half the expected length is a fake, sample or truncated download, so the exact release is excluded as `release_incomplete` and the next candidate is tried. A season pack fails on its short file instead of publishing a broken episode. Unknown runtimes only reject a movie under 10 minutes or an episode under 3 minutes; titles whose expected runtime is under 12 minutes, season-zero specials and files whose duration cannot be read are never judged. No extra probe or provider call is made.

- One stuck task can no longer stop Media Manager's background work. The worker handles one event at a time, and on 2026-10-17 a read blocked inside the AltMount mount (a FUSE read no timeout can interrupt) held it for two hours: no searches, downloads, publications, repairs or Seerr updates. Each handler now runs under a time limit (30 minutes, 3 hours for backups). Past it, the handler is cancelled; if it still does not return within 30 seconds it is abandoned, its event is retried 10 minutes later, and the worker moves on. A panicking handler is retried instead of stopping the process. Opening and sampling a media file for inspection is bounded by the probe timeout: a file that does not answer is inspected again 10 minutes later (`altmount_output_unresponsive`). It is never treated as a bad release, and ffprobe output pipes no longer keep a killed probe waiting.

- Quality profiles can require **audio** languages (`required_audio_languages`, the "Required audio languages" field in Settings → Quality profiles). A profile requiring Danish audio accepts only a Danish dub: subtitles do not count. Release selection holds a release until its name shows Danish audio (`DKaudio`, `DANISH.DUB`, `Dansk.Tale`, or a bare `DANISH`/`DANSK` tag that does not also say subtitles), and output inspection fails any file without a Danish-tagged audio track, so the next release is tried. A tagged audio track in another language beats a name hint. A title made in the required language needs no tag: its releases are accepted and its untagged audio track counts as that language. Seerr's Auto route sends kids titles to a profile requiring Danish audio when one exists.

- Existing files in a library that requires an audio language are upgraded by themselves. The 30-minute repair sweep asks Plex which files lack the language (`audioLanguage!=dan`) and opens an upgrade for each, through the same machinery as broken-file repairs (`GET /api/v1/repairs` now reports `reason` and `retry_after`). The old file keeps playing until Plex confirms the dub. Upgrades are paced: at most 40 search at a time, 10 new per sweep, movies first. One that finds nothing in 7 days is closed as `not_found`, and its file is retried after 60 days. Titles made in the required language are `skipped`, and only AltMount symlinks are ever replaced. Schema 46 adds `reason`, `created_workflow` and `retry_after` to `altmount_repairs`.

- A Seerr request for a season TMDB does not list (for example a newer season only TheTVDB knows) no longer fails its intake forever. Seerr answers HTTP 500 for such a season; intake now skips the lookup, and an actionable season without an episode list is reported as needing attention, naming the season. Request 368 had retried 3,500 times since 2026-10-07.

- A required language (for example Danish) is now satisfied by a subtitle **or an audio track** in that language: a Danish dub needs no Danish subtitles. Output inspection checks audio-track languages next to subtitles, release selection treats explicit Danish-audio names (`DKaudio`, `DANISH.DUB`, `Dansk.Tale`) as positive evidence, and an already published dub is not treated as missing the language when looking for upgrades. A bare `DANISH` tag stays unknown, as before.

- Moving a title to another library (`POST /api/v1/workflows/{id}/relocate-links`) now moves its published subtitle sidecars too (only "verified" ones moved before, so relocated titles lost their Danish subtitles in Plex), keeps the scheduled search of a waiting workflow (relocation bumps the revision and the pending search used to be dropped as stale), and also accepts open workflows that have nothing published yet, so the waiting episodes of a moved series publish into the new library. New `PATCH /api/v1/settings/library-roots/{id}` makes a root the default for its media kind or disables a root that nothing uses any more.

- An AltMount restart or FUSE remount no longer leaves the API with a dead mount. Compose binds the directory containing AltMount's mount point (`ALTMOUNT_HOST_PARENT_PATH`, default `/mnt`) read-only at `/mnt` with `rslave` propagation instead of binding the mount point itself, so a new mount reaches the running API. `ALTMOUNT_HOST_PATH` is no longer used. While the read-only root is unreadable, AltMount reconciles and output inspection wait and retry (`altmount_mount_unavailable`) instead of failing workflows as `altmount_output_unavailable` or `output_inspection_failed`; no release is excluded for a mount outage. System health reports each AltMount output mount, and the Overview tile and sidebar warn when it is unavailable. AltMount companion patches fix the crash behind the 2026-10-06 outage (a race in the AES decrypt reader), keep the mount up when any single FUSE request panics, and add a read-only kernel mount. On 2026-10-06 a dead bind failed 118 workflows over eleven days.

- Acquisition budgets are configurable at startup: one–six attempts per new round (default two) and one–twelve retained failed outputs (default four). Schema 43 widens slot constraints without rewriting historical limits; UI and owner recovery use the configured budgets. Failed outputs, exact exclusions and provider pacing stay enforced.

- The Compose API container explicitly disables IPv6 so indexer requests use the host's IPv4 egress identity even if its external Docker network later enables IPv6. Per-provider pacing, budgets, redirect pinning, and credential boundaries remain unchanged. Other containers and host IPv6 are unaffected.

### Added

- Workflows offers “Retry access-rejected release” after provider access is repaired. The owner confirms the exact selected release and workflow revision; only pre-submission HTTP 401/403 exclusions in the existing open round can be lifted, including the exact historical failure messages from before schema 41. The action preserves the original rejection in audit history and queues normal paced retrieval without searching or opening a round. Payload, output, owner-block, policy, retained-output and submission guards remain in force.

- Read-only console screens now keep themselves current. Overview, Library, Requests, Wanted, Calendar, component health, tasks, and title pages re-read Media Manager's persisted state every 15 seconds (Workflows every 8), pausing in a background tab and catching up when it is visible again, so download progress and request decisions show without pressing Refresh. Form and settings screens stay manual.
- The Requests page follows Seerr's own state for requests intake saw before approval: "Awaiting approval" while pending (still under Needs attention), "Approved in Seerr" once approved (active, not success, until intake admits it), and "Declined" once declined, which no longer counts as needing attention.
- Owner actions in the console: Approve and Decline for Seerr requests that are still pending there (the decision is made in Seerr, audited, and followed by normal intake; declining asks first), and "Re-check Plex" for titles whose Plex confirmation timed out, which re-queues the existing exact-path confirmation for each of them within its retry limit and never requests a library-wide scan.
- Real download progress and per-episode detail in the owner console. Media Manager now keeps the percentage and stage AltMount reports for the in-flight attempt (schema 42) and shows it as "AltMount 74%"; nothing is estimated, and no percentage is shown when AltMount reports none. TV title pages list every expected episode with its air date and status (acquired, acquiring, needs attention, not yet acquired, unaired), and the Overview core tile shows API uptime from the new `started_at` system-info field.
- An owner-console redesign: a dark indigo palette with the Inter typeface bundled locally, a regrouped sidebar (Overview, Library, Intake, Operations, Sources, Settings, System, Advanced) with search and a live system-status chip, and rebuilt Overview, Movies, TV Shows, title, Wanted, Requests, and Workflows pages. Attention items now explain in plain language what happened, whether Media Manager retries on its own, and what the owner can do; progress is shown as an eight-step stage stepper driven only by persisted state. The backend and API are unchanged.
- A redesigned owner console. Every screen now colours itself through semantic design tokens with a dark (default) and a light theme, selectable per browser as dark, light, or system and applied before first paint. The shell gains an icon-collapsible sidebar with live attention and active-work counts, breadcrumbs, an attention bell that shows its count before opening, and a mobile tab bar; movie and series pages become a hero with Overview, Seasons, Workflows, and Files tabs. Geist fonts are bundled locally, so no font CDN is contacted.
- A browser route tour that visits every route in the dark and light themes and on mobile, asserting no console errors, no unexpected requests, no horizontal overflow, and no serious accessibility violations; GitHub Actions now runs the browser suite alongside GitLab CI.
- Seerr sees a single root folder, `/srv/media/Auto`, from Media Manager's Radarr/Sonarr API. Media Manager routes Auto requests from metadata: kids content to `Børn Film`/`Børn Serier` with the profile that has no required subtitles, documentaries to `Dokumentar`/`Dokumentar Serie`, Christmas titles to `Julefilm`/`Julekalender`, Danish originals to `Danske Film`/`Dansk Tv-Serier`, and everything else to the kind's default root. A missing themed root falls back to the default root; requests carrying an explicit legacy root keep their existing routing.
- A Seerr request for a movie or season that is already Plex-confirmed attaches to the existing workflow and queues the Seerr availability sync instead of downloading it again (delivery outcome `already_available`); mixed requests create workflows only for the missing seasons.
- `POST /api/v1/workflows/{id}/relocate-links` moves a published workflow's current Plex-facing links and verified subtitle companions to another enabled library root of the same media kind, updating `library_links.root_id`, the workflow root, and an audit event (`library.links_relocated`). Link targets and AltMount content are never touched, destinations are never overwritten, and a partially applied move is completed by a rerun. It exists so a movie published into the wrong Plex folder (for example before Seerr root routing existed) can be corrected without re-downloading.
- `POST /api/v1/workflows/{id}/acquisition-rounds/from-known` opens one two-slot round from releases already observed and judged eligible under the profile's current policy, ordered by explicit Danish-subtitle evidence, then a Danish/Nordic title marker, then score, and selects the best known candidate directly. It unblocks the 23 workflows that used both attempts and were waiting for a genuinely new post while untried eligible releases (6 with explicit `da`) sat known.
- `POST /api/v1/workflows/{id}/revive-rejected-archives` revives archive releases the pre-flight screen refused before AltMount ever saw them (60 exclusions), removing their attempt markers, package guards, and exclusion rows with an audit event; queue-time archive failures stay excluded.
- A completed season that is entirely missing but whose searches have only ever observed episode releases (no season pack) now dispatches per-episode acquisition through the existing airing path, because Danish TV is posted per episode. This unblocks Forbrydelser der rystede Danmark, Extreme Makeover, Rivalerne, and Reacher.
- A Radarr/Sonarr-compatible API (`/radarr/api/v3`, `/sonarr/api/v3`, guarded by `SERVARR_API_KEY`) so Seerr can use Media Manager as its only server: it exposes Media Manager's library roots and quality profiles, acknowledges adds without creating a second catalog, and reports Plex-confirmed availability for scans. Existing requests keep working through the Seerr root-folder routes.
- Seerr request routing: the service root folder and profile chosen in Seerr are persisted as request provenance and resolved through owner-created mappings in Settings → Connections; an unmapped folder pauses the request with an exact reason instead of publishing into the wrong library, and saving a mapping requeues paused requests immediately.
- A complete documentation set under `docs/` (onboarding, architecture, operations, reference, status, archive) with an index, package-level Go doc comments for every package, and a `docs:check` link/anchor validator wired into CI.

- A credential-safe live Playwright acceptance suite for every deployed route across desktop, tablet, and mobile viewports.

### Changed

- Danish subtitles remain **required** for foreign content on the two `Best Available Danish Subs` quality profiles (`required_subtitle_languages: ["da"]`); a same-day experiment that relaxed them to preferred was reverted at owner direction before any relaxed-policy output was verified or published. Output verification enforces the union of the attempt's round snapshot and the profile's current required languages, so a later tightening also applies to a job already in flight. Danish-original routing is unchanged.
- AltMount packages are screened before submission: an NZB whose manifest contains only archive sets, ISO/DVD structures, or other non-playable containers is rejected without an upload. AltMount queue failures caused by archives, unplayable manifests, or missing Usenet segments now exclude the exact release and package and retry another candidate inside the open acquisition round instead of parking the workflow as infrastructure attention. If AltMount has already pruned the failed queue entry, the persisted failure detail drives the same decision instead of retrying the reconcile forever.
- Movie-library assembly now indexes related files, wanted items, and workflows once and reuses precomputed search text, avoiding quadratic work as the catalog grows.
- Catalog loading now retrieves every API page in bounded 200-record batches instead of silently presenting a truncated library.
- Library contrast, typography, responsive sizing, and inspector readability were improved without changing the approved composition.
- Newznab search requests now honor each commissioned provider's supported dialect and independently persisted query/grab budget.
- Equal-score release selection uses deterministic durable identities rather than response timing.
- Indexer cooldown work is deferred without blocking the worker or consuming an acquisition attempt.

### Fixed

- treasure-maps NZB downloads work again. Its `t=get` redirects to a separate file host with the API key in the URL; Media Manager strips keys from redirects, so every grab since 2026-08-31 failed with HTTP 403. treasure-maps now has its own verified direct-download contract, `https://file.treasure-maps.com/getnzb/<32-hex release ID>?r=<key>`, requested directly without a redirect and built from the stored release ID, so existing candidates recover too. `/details/<32 hex>` permalinks resolve to the same ID. The redirect credential policy and every other provider's download path are unchanged.
- The Add media page's season box starts empty in both modes (it was prefilled with `1:10` for manual entry and `1` after choosing a Seerr result), shows format errors inline, and keeps Add disabled until the seasons are valid, matching the title page's Add season box.
- The title page's "Add season" box starts empty instead of prefilled with `1:10`, so one click can no longer add a blank ten-episode season 1 that searches at once (this created a duplicate Reacher season 1 that re-searched for two weeks). A season that already has an active season workflow is refused with a pointer to that workflow; a season already in Plex, partly in Plex, or with episode work in progress needs an explicit "Search again anyway" confirmation.
- A request Seerr has completed no longer stays under Needs attention because of an intake outcome recorded by older builds ("the request changed after retrieval started", written when Completed was read as a revocation). Once no linked workflow needs anything, it shows as Available; requests whose workflows still need attention, and approved requests whose intake needs attention, are unchanged.
- TV title pages no longer call a season "currently airing" or its episodes "unaired" just because the stored episode snapshot has no air dates (Reacher season 1 showed "10 unaired" with every episode in Plex). Episodes without an air date are now counted and shown as "air date unknown" (`undated_episodes`); only dated future episodes are unaired. Season counts now come from the same newest snapshot the episode list shows, and a cancelled duplicate season workflow no longer replaces the live one on the title page.
- The Workflows table fits a 1440 px screen and keeps text inside its cells. Table cells never wrapped, so long attention details were drawn across the Recovery column and the table grew to over 2,000 px, hiding Updated and Actions behind a sideways scroll. State and Recovery text now wraps within fixed column widths (long release names included) and action buttons wrap.
- The Calendar lists each episode once. An airing season's episodes are expected by both the season workflow and their own episode workflow, so every episode appeared twice (for example "Waiting" and "Plex confirmed"). The row now shows the most informative workflow: a live one before a cancelled one, a Plex-confirmed one first, then the episode's own workflow.
- The owner can cancel a workflow that needs attention once none of its AltMount jobs is active. The console already offered Cancel for these workflows, but the API refused every one of them with "workflow can no longer be cancelled safely". Pre-retrieval work cancels as before, work that is retrieving, verifying or publishing is still refused, and a cancelled workflow's jobs and retained output stay untouched and owner-visible.
- A Seerr request that Seerr itself marks Completed (status 5, set when it sees the media available through its Plex or *arr scan, or Media Manager's own availability sync) is no longer treated as revoked. Intake previously ran the revocation path for every status except approved, so waiting workflows were cancelled, failed ones were flagged `seerr_request_revoked`, and the Requests page showed the request as "Awaiting approval" under Needs attention. Completed requests are now recorded as `already_available`, their workflows keep their state, and requests recorded by older builds show as Available (Seerr Failed shows as Failed).
- A title page names the quality profile its workflows acquire under before any file exists, instead of "Not assigned" (found in the production upgrade rehearsal).
- Review of the owner-console work: Approve and Decline on the Overview no longer navigate away (the row was a link around the buttons); a downloading workflow shows on the Download step, not Submit; a long non-ASCII AltMount stage label can no longer make PostgreSQL reject the job update; the title page lists only the newest episode expectation, so an episode removed by a correction no longer shows as missing; and "Re-check Plex" can no longer be starved by workflows at their retry limit, and reports real failures as failures instead of skipped items.
- The API process no longer crashes when a Seerr request arrives and any of the optional direct metadata providers (TMDB, TVDB, Simkl) has no credential. The default Compose secrets are empty files, so an unconfigured provider was wired as a nil client and the first metadata enrichment dereferenced it; unconfigured providers now stay unwired and intake falls back to Seerr's TMDB data as intended.
- An owner decision on a Seerr request now stores the status Seerr confirmed straight away, so the request's Approve and Decline buttons disappear as soon as Seerr accepts the decision instead of staying visible until intake re-reads the request. Intake still re-reads it from Seerr.
- The local Playwright web server could not start after the `cloudflare:` loader was added only to the container; it now registers the same loader.
- Seerr routing selects and season progress bars had no accessible names, the overview scrolled horizontally by a few pixels on phones, and native selects with long release titles overflowed their forms.
- Revoking a Seerr request (deleted or no longer approved) now also stops the single-episode workflows dispatched from its season: pre-retrieval episodes are cancelled and retrieving ones need owner attention. Previously only the season workflow was cancelled, and its episodes kept searching and downloading. Episodes of a season another approved request still tracks are kept.
- Seasons acquired episode by episode (airing seasons and Danish TV posted only per episode) now reach Seerr: a season is reported available once every expected episode is Plex-confirmed, and confirmed episodes of an incomplete season mark the media partially available. Previously only a Plex-confirmed season workflow counted, and episode workflows never triggered a sync, so these requests stayed "requested" indefinitely. The 5-minute bootstrap backfills existing confirmed episodes once per media.
- A Seerr request attached to content that was already synced for an earlier request now queues its own availability sync; it previously collided with the earlier sync event for the same workflow revision and was silently dropped.
- Seerr snapshots whose payload changed without a newer `updatedAt` cursor are now accepted instead of failing as a conflict on every poll (36 requests, ~17k deliveries). Approved requests whose current snapshot never produced a workflow are re-evaluated, and polling retries them with a 24-hour backoff.
- The UI container runs the Workers-targeted bundle under Node by resolving `cloudflare:` imports to an inert module (`NODE_OPTIONS=--import=...register-cloudflare-loader.mjs`).
- NZB retrieval failures now select a known eligible alternative within the same open round, bounded to four failed candidates separately from the two download slots. HTTP 401/403 avoids the rejected provider for that round; storage, round, policy and blocklist admission run before a grab. Danish-required searches prefer explicit subtitle evidence, then Danish/Nordic clues, without changing eligibility or output verification. Additive schema 41 does not retry parked requests automatically.

- The package manifest is screened **before** the AltMount submission intent, so a zip/tar/ISO/non-playable rejection excludes the release and queues the next search without creating a job or spending one of the round's two attempt slots (`RecordPreSubmissionRejection`).
- RAR and 7-Zip releases are submitted to AltMount instead of being rejected before upload. AltMount streams stored and nested RAR itself (77 of 84 RAR analyses succeeded in 72 hours, including Media Manager's own DKsubs and NORDiC uploads); the screen had rejected 60 releases, many of them the Danish scene posts being searched for. Archives AltMount cannot stream remain release-attributable failures; zip/tar and ISO/DVD are still rejected.
- A movie release whose provider identity exactly matches the verified IMDb/TMDB identity is no longer held for lacking the metadata year in its title (1,041 held candidates across 23 workflows, all with a matching identity).
- Danish titles are matched and searched in scene spelling (`Forræder` → `Forraeder`, digraph and single-letter folds, `&` as `and`, apostrophes dropped). No title containing æ/ø/å had ever been confirmed; genuine `Forraeder.Under.Kutten...DANiSH` releases were rejected as the wrong title.
- Searches that select nothing back off (30 minutes doubling to 12 hours per round) instead of re-querying all nine indexers every 30 minutes; repeat empty searches had exhausted every indexer's daily query budget.
- A selection whose indexer has exhausted its grab budget moves to the identical release on an indexer with budget left instead of idling until the window resets (44 of 46 pending selections were waiting on one indexer).

- Acquisition selection no longer strands known eligible releases behind a round's novelty cutoff. The selector still prefers releases first observed after the cutoff, but now falls back to any eligible release that was never attempted or excluded instead of parking the workflow as held forever. The submission-intent gate and the duplicate-package fallback apply the same preference. This unblocks 67 open rounds where every eligible candidate (5,154 releases, many with explicit Danish-subtitle evidence) predated a restored cutoff.
- The Radarr/Sonarr add and command handlers now accept the real client payloads Seerr sends (`profileId`, `minimumAvailability`, `addOptions`, `searchNow`, `seasons`, `seasonFolder`, `seriesType`, `tags`, `movieIds`, ...). Strict JSON decoding rejected every add with HTTP 400, so Seerr marked new requests FAILED before Media Manager's intake ever saw them.
- Msgnews download locators now request the canonical `www.msgnews.live` host directly. The provider 308-redirects the bare host while carrying the API key in the path, which the cross-origin credential policy correctly rejected; requesting the canonical host keeps the key on the same registrable site without weakening redirect pinning or credential stripping.

### Security

- Every Newznab NZB request, including each of at most two redirects, rechecks the workflow revision and selected candidate immediately before sending.
- Cross-origin NZB redirects use per-hop public-address validation and literal-IP pinning while preserving TLS hostname verification and stripping credentials, Referer, and origin-specific headers.
- Newznab observation URLs are sanitized before persistence, including nested and percent-encoded credential parameters; historical observations were corrected without deleting evidence.
- Secret files, environment files, runtime data, generated output, and deployment credentials remain excluded from version control.
